- **Behaviour change (PostgreSQL)**: a `columns:` override that declares a `date`, `time`, `timestamp`, `timestamptz` or array column `text` is now read through the server's own text (`col::text`, timestamps rendered in UTC) instead of being refused `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH`, so a value the native column cannot hold (`infinity` and `-infinity`, a date of 5874897-12-31, `24:00:00`, a multi-dimensional array, an array element of those) is delivered losslessly as that text on every row. The refusal that names such a value (`RIVET_SOURCE_VALUE_UNREPRESENTABLE`, exit 5) now ends with the remedy: declare the column `text` under `columns:`, or project it in the export's `query:`. A column with no override, and every other override pair, behaves as before; nothing written before the upgrade changes, and a `text` override that was refused before the upgrade now runs. A PostgreSQL CDC export with a pending baseline (`initial: snapshot` or `backfill:`) still refuses that declaration for those columns, `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1) from `run`, `check` and `doctor` before a row is delivered, because the change stream renders the same cell in its own form and one `__changes` log would hold two spellings of it; remove the column from `columns:`. A stream-only export and a baseline already done are unchanged.
- **Behaviour change (PostgreSQL)**: an incremental export whose `cursor_column` is a `date`, `timestamp` or `timestamptz` column declared `text` under `columns:` is refused `RIVET_PLAN_CURSOR_TYPE_UNSUPPORTED` (exit 5) by plan, `check`, `doctor` and `run` before a row is delivered, because the text order is not the time order; remove the column from `columns:`. A `text` cursor column and an undeclared temporal cursor are unchanged.
