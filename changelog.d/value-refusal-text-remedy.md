- **Behaviour change (PostgreSQL)**: a `columns:` override that declares a `date`, `time`, `timestamp`, `timestamptz` or array column `text` is now read through the server's own text (`col::text`) instead of being refused `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH`, so a value the native column cannot hold (`infinity` and `-infinity`, a date of 5874897-12-31, `24:00:00`, a multi-dimensional array, an array element of those) is delivered losslessly as that text on every row. The refusal that names such a value (`RIVET_SOURCE_VALUE_UNREPRESENTABLE`, exit 5) now ends with the remedy: declare the column `text` under `columns:`, or project it in the export's `query:`. A column with no override, and every other override pair, behaves as before; nothing written before the upgrade changes, and a `text` override that was refused before the upgrade now runs.
