- **SQL Server `MONEY` and `SMALLMONEY` are delivered exact over their whole range, on batch and CDC.** Behaviour change. The driver decoded money as a 64-bit float, so a value of 9e11 or more (`MONEY` runs to ±922337203685477.5807) was stopped by rivet: a batch export exited 5 with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` and a CDC run with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED`. The pinned driver now decodes money as a decimal at scale 4, so those values are written as `Decimal128(19, 4)` exactly, and an export or CDC run that stopped on one resumes and delivers it with no change to the config. Two neighbours change with it: A `columns:` override of `decimal(p,s)` with fewer than four decimals over a money column used to round the value silently (`123.4567` as `123.46` under `decimal(19,2)`); it now refuses a value it would round, `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1), and delivers a value that fits, so declare `decimal(19,4)` (the default) or leave the override out, or round in the query. A `sql_variant` holding a money value of 9e11 or more is written exact (it was rounded to one decimal). A money column used as an incremental cursor is unchanged: the stored cursor is the same text before and after. Parts already written by an earlier run are unchanged.
