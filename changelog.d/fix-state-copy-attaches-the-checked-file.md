- **`rivet state copy` from a SQLite state whose path holds `#`, `?` or `%` copied nothing and reported success.** The copy attached the source as a `file:` URI built from the raw path, so `a#b/.rivet_state.db` was cut at the `#`: SQLite created an empty file `a` beside the directory, the copy reported `20 table(s), 0 row(s)` with exit 0, and the note told the operator to switch to the empty PostgreSQL state. A path holding `%41` read the file under `aAb` when that existed. **Now** the path is percent-encoded into the URI, so the attached file is the file the guard checked, and a source that holds no cursor and no run after the attach stops with `RIVET_STATE_COPY_SOURCE_EMPTY` (exit 1) before the target is touched. A copy from a path without those characters is unchanged. **What to do:** if you ran `rivet state copy` from such a path on an earlier release, the PostgreSQL state it filled holds no rows: drop it, run the copy again, and delete the stray empty file beside the directory.
