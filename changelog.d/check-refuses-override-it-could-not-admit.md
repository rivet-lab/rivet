- **`rivet check`, `doctor` and `plan` refuse a `columns:` override they could not admit because the source connection failed.** Behaviour change. `check`, `doctor` and `plan` read the source catalog to decide an override (`RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH`, `RIVET_TYPE_UNSAFE_MAPPING`) before any row is written. When that connection failed (for example Oracle's listener refusing it with ORA-12516 while several checks run at once), the export was planned without the catalog and `check` exited 0, then `run` refused the same override by code. **Now** an export that declares `columns:` and could not be admitted for want of a connection stops with `RIVET_SOURCE_CONNECT_FAILED` (exit 2) naming the export and the driver's own words. An export with no `columns:` override is planned as before, and a `columns_from: grants` export still stops on the connect failure. State, files and tables written before the upgrade are untouched. **What to do:** rerun `check` once the source accepts connections (lower the number of concurrent checks against a listener that limits them).
