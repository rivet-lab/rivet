- **A whole-config `rivet check` and `rivet doctor` treated a CDC backfill recipe as an export of its own.** `check` described the recipe (`Export: <recipe>`), planned it, counted its columns a second time in the `--target` note, and rejected a config over the recipe's unused `destination` (for example `RIVET_PLAN_REJECTED [stdout-no-keyset]`) that `plan` and `run` never use; `doctor` probed that destination too. **Now** `check`, its planner and `doctor` take the exports `run` runs (`config::declared_exports`), so a recipe is neither listed, planned, counted nor probed, and `rivet check --export <recipe>` still grades it alone. **Behaviour change:** a config that `check` refused only because of a recipe's destination or planner verdict now passes `check`; a `--target` note counts each refused column once per loaded table. Nothing written before the upgrade changes: `check` and `doctor` write no state. **What to do:** nothing; to grade the recipe's own read, run `rivet check --export <recipe>`.
