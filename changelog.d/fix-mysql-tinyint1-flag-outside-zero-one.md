- **A MySQL `TINYINT(1)` flag holding a value outside 0 and 1 was delivered as `true`; it is now refused.** Behaviour change. A `TINYINT(1)` (or `TINYINT(1) UNSIGNED`) column read as a boolean delivered 2, 5, -1, 127 or 255 as `true` with exit 0 in a batch export and in a CDC stream. **Now** a `TINYINT(1)` column (also under a `bool` override) delivers 0 as `false`, 1 as `true` and NULL as NULL, and refuses any other value `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) naming the column and the value, before a part is written and before a stream's checkpoint moves; the column stays `Boolean`, and `BIT(1)` is unchanged. Parts and tables written before the upgrade are untouched; rows already delivered as `true` keep that value. **What to do:** correct the values to 0 and 1, or declare the column `columns: { c: int64 }` to carry the number as it is; after a stream refusal, follow the re-baseline step the refusal prints.
