- **`source.columns_from: grants` is now accepted on MongoDB (behaviour change; refs #715).** Through the previous release a MongoDB config carrying the key was refused at load with `RIVET_CONFIG_SOURCE_MODE_UNSUPPORTED`, and the refusal of every other engine named "MySQL sources only". **Now** a MongoDB source with `columns_from: grants` delivers only the fields of a view of the collection whose single stage is a `$project`: a batch read goes through the view and is refused with `RIVET_SOURCE_COLUMNS_UNREADABLE` when the account can read the collection itself, no view or two views expose it, the view is not a single `$project` or drops `_id`, or the connection holds no credentials; a CDC run watches the collection and removes the hidden fields inside the server's change-stream pipeline (data minimisation, not access control; `rivet check` and the run log say so), delivers no row for an update of hidden fields only and still advances the checkpoint. The refusal on PostgreSQL, SQL Server and Oracle now reads "supported on MySQL and MongoDB sources only". A batch read of a view no longer sets `noCursorTimeout`, which the server refused with code 168. State and tables written before the upgrade are untouched: a config without the key reads and delivers every field as before, and a config that carried the key never ran. **What to do:** nothing for configs without the key; to use it on MongoDB create `db.createView('<view>', '<collection>', [{$project: {<field>: 1}}])` keeping `_id`, grant the account `find` on the view and `listCollections` on the database, and (batch) no `find` or `changeStream` on the collection itself. The `mongo-auth-rs` compose profile (port 27021) is the new stand of the cells.
