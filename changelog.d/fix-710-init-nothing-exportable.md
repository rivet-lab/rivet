- **`rivet init` refuses a scaffold that would hold no export.** A MongoDB batch init where every collection name fails the `table:` identifier gate wrote a `rivet.yaml` with only `# SKIPPED` comments and an empty `exports:`, which rivet then failed to load as a config (0.32.2 and earlier). The unreleased Oracle CDC skip of tables LogMiner cannot mine (a LOB column, a name over 30 bytes, ...) did the same for `init --mode cdc`. **Now** init stops with `RIVET_INIT_NOTHING_EXPORTABLE` (exit 5), names each table with its skip reason, and writes nothing. **What to do:** fix what the reason names (an Oracle CDC skip clears with a batch `--mode`), or init the schema with `--include` naming a table it can export.
- **Behaviour change: `rivet init --mode cdc` leaves out a table whose name cannot be a `table:` shortcut, on every engine.** A CDC export reads its baseline through `table:`, and the config gate accepts at most two segments of letters, digits and `_` that do not start with a digit; a hyphen, a space, a leading digit or a non-ASCII name scaffolded a CDC export that `rivet run` then refused with `RIVET_CONFIG_EXPORT_SOURCE_INVALID` (MongoDB: init wrote it and the run failed; PostgreSQL, MySQL, SQL Server and Oracle the same). **Now** such a table gets a `# SKIPPED` comment naming the gate, beside a table that can run, and a CDC init of only such tables stops with `RIVET_INIT_NOTHING_EXPORTABLE` (exit 5) writing nothing. **What to do:** rename the table, or export it with `query:` in a batch mode (a MongoDB collection has no other form: rename it or export it with another tool). Configs written before the upgrade are unchanged on disk; re-run `rivet init --mode cdc` to see which tables are now left out.
- The `# SKIPPED collection` comment that `rivet init` writes for a MongoDB collection beside an exportable one is re-wrapped at 100 columns (three lines where four were hand-wrapped); a script that matched the old line breaks must match the first line, `# SKIPPED collection <name>:`.
