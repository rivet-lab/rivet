- **Behaviour change: a MySQL zero or partial date (`0000-00-00`, `0000-00-00 00:00:00`, `2026-00-00`) written as NULL left no trace.** Batch and CDC runs wrote NULL for such a DATE, DATETIME or TIMESTAMP cell since the first release, with no log line and nothing in the summary, so a column that lost values looked the same as one that never had them. **Now** the value is still NULL and the exit code is still 0, and the run prints a WARN naming the column and the count (``column `d`: 2 MySQL zero or partial date value(s) written as NULL``) and the batch summary gains a `fidelity` row with the same counts. Tables and files written before the upgrade are unchanged, they already held NULL. **What to do:** nothing; to keep the original value, select the column as text in the export query (`CAST(col AS CHAR)`).
