- **A MySQL ENUM or SET label holding a character outside the Basic Multilingual Plane (an emoji, for example) was delivered as `?` by CDC.** Behaviour change. MySQL prints such a label as `?` in every catalog rendering (`information_schema.columns`, `SHOW COLUMNS`, `SHOW CREATE TABLE`), and the stream read the labels from the catalog, so the cell was a changed value with exit 0. **Now** the labels come from the binlog table map (`binlog_row_metadata = FULL`, which a CDC run already requires) for every column whose label the catalog cannot spell; a column whose labels the catalog spells exactly is read as before. When the table map carries no labels for such a column, a cell holding a `?` label stops the run with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (exit 5) naming the table, the column and `SET PERSIST binlog_row_metadata = FULL;`, never a `?`. An ENUM declared with a hex literal (`enum(x'..')`) that the catalog refused before is now delivered when the table map lists its labels. Rows and checkpoints written before the upgrade are untouched; a row already delivered as `?` stays so until the table is re-snapshotted (`cdc.initial: snapshot` after emptying the destination). **What to do:** nothing for a source on `binlog_row_metadata = FULL`; otherwise run `SET PERSIST binlog_row_metadata = FULL;` and re-run.
