- **Behaviour change: a run whose manifest never landed is now recorded `failed` in `rivet journal` and on the run card; before, both said `success`.** When the destination refused the terminal `manifest.json` write (a directory in its place, a permission or quota stop), the run exited non-zero and its run-status ledger row, metrics row, report and notification said `failed`, but the journal row was written first and stayed `success` with no error, and the card of a multi-export or parallel run stayed `✓` (0.32.2 and earlier, `rivet run` and `rivet apply` alike). **Now** the manifest is written before the journal row, the card and the ledger row are finished, so all of them carry the same status and the journal's `error:` line names the manifest write. **What to do:** nothing for new runs. A journal row written before the upgrade for such a run still reads `success`; the run's `rivet metrics` row said `failed`, so read that for runs before the upgrade, and re-run the export to land the manifest.
