- **Behaviour change**: a nanosecond zoned timestamp column (SQL Server `datetimeoffset(7)`, or a `timestamp_tz_ns` override) now lands in BigQuery as INT64 UTC nanoseconds since the epoch, as the naive nanosecond timestamp already did. Before, the load declared TIMESTAMP over the Parquet nanosecond column: BigQuery read every value as microseconds (1970-01-02 03:04:05 came back as 1973-02-01 20:03:20) or rejected the load with `RIVET_LOAD_WAREHOUSE_REJECTED`. A table written before the upgrade holds those wrong TIMESTAMP values and is not rewritten: drop it and reload, or declare the column `timestamp_tz` under the export's `columns:` to keep a microsecond TIMESTAMP (sub-microsecond digits dropped). Other targets and `datetimeoffset(0..6)` are unchanged.
