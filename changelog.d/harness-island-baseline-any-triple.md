- **Harness: `make release-oracle-prev-bin` could not fetch a baseline on Linux x86_64.** The latest release came from `gh release list`, and the three pinned carriers from `gh release download --pattern "*aarch64-apple-darwin*"` into hard-coded Darwin file names, so the measuring island (`make release-oracle-island`) ran only on the one machine and OS the Makefile was written on. The baseline and every carrier now go through `dev/release_oracle/field_state.py`, the fetcher the field releases already used (`--fetch-release <dir> <tag | latest>`): the asset for the machine's triple is downloaded from the public release, checked against the release's `SHA256SUMS.txt`, and unpacked where `$(TRIPLE)` (`field_state --triple`) puts it; `latest` is where the public `releases/latest` page redirects (the API answers 403 after 60 calls an hour per address), so `gh` is not needed. On Linux the `-glibc2.28` build is taken when the release publishes one (the default build needs glibc 2.38 and does not start on older hosts) and unpacked under the machine triple's name. A release with no asset for the machine, or one that does not start on it, fails its fetch by name; only the baseline's failure stops `release-oracle-prev-bin`, and a carrier that is missing fails the cells that run it, as before. `tests/offline/field_state_guard.rs` fails when the Makefile spells a triple, `uname` or `gh release` again, and the fetcher's self-test grades a whole, a tampered and an absent asset and the glibc choice. No product behaviour changes. **What to do:** nothing.
