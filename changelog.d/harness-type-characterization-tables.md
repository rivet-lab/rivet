- **The PostgreSQL, SQL Server and Oracle type mappers had no table that pinned what each native type becomes.** A refactor of how native types map to Rivet types could change a delivery form, a fidelity or the override pairs a type reads, and no offline test would name the type. **Now** one table per engine (`the_postgres_type_table_is_pinned`, `the_mssql_type_table_is_pinned`, `the_oracle_type_table_is_pinned`) pins, per native type, the Rivet type, the Arrow type, the delivery form (native, text form or unsupported), the fidelity and every source-to-target override pair `override_table` reads; one helper in `src/types/characterization.rs` renders the lines and prints every differing row. A row that is a known red carries its `known_red.py` class (`# red:CLASS`), checked against the ledger, so a renamed or removed class fails the test; a row another change is moving carries `# under-change`. No product code changed.
