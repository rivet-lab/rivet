- **A cursor's nullability was read by the column's output name, so `COALESCE(c, d) AS c` over a nullable `c` was refused `RIVET_PLAN_CURSOR_NULLABLE` on SQL Server and Oracle, and a PostgreSQL view over a nullable column was admitted (#947, see #966).** **Now** SQL Server and Oracle claim a column nullable only when the query selects a table column as it is (`c`, `t.c`, `c AS x`, `*`) and that table column is nullable in the catalog; an aliased expression is not claimed either way, so `CAST(c AS BIGINT) AS c` over a nullable `c` is no longer refused there (behaviour change against unreleased #947; the remedy for a NULL-holding expression is `incremental_cursor_mode: coalesce`). PostgreSQL follows a view column through the view's definition to its base column, so a view over a nullable column is refused and one over a NOT NULL column runs as before. **What to do:** nothing.
