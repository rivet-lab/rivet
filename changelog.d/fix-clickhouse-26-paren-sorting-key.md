- **A CDC or incremental load into an existing ClickHouse change log was refused on ClickHouse 26.8 and later.** rivet creates the log `ORDER BY (`id`)`; ClickHouse 26 keeps those parentheses in `system.tables.sorting_key`, and rivet read `(id)` as another key than `load.pk`, so every load after the first stopped with `RIVET_LOAD_TARGET_OBJECT_CONFLICT` ("collapses versions by ((id))"). **Now** a key wrapped whole in one pair of parentheses is read without them. **Changed stop:** that refusal no longer happens for an unchanged key; a log whose key really differs is still refused. The release gate's ClickHouse load cells run on the stand's default server, 24.8 (`RIVET_CLICKHOUSE_TAG` picks the version, `docker-compose.yaml`); `dev/clickhouse/version_matrix.py` runs the same cells on 24.8, 25.8, 26.3, 26.8 and 26.10 only when it is started by hand, and nothing in the Makefile, the workflows or the gate calls it.
