- **Behaviour change: `rivet state reset --export <name>` of a `partition_by` export now clears the progress of its partitions; before, it printed "State reset" and cleared nothing.** The cursor and progression of such an export are held per partition, under `<name>__<value>`; the reset looked for the declared name only, so the next run exited 0 with `_SUCCESS` and no parquet in every partition, and a destination emptied on the documented advice stayed empty with `validate` green. The refusals that print `rivet state reset --export <name>__2026-01-01` also ended in `RIVET_CLI_EXPORT_UNKNOWN`. **Now** a reset of the declared name clears the export's own rows and every stored partition's rows (cursor and progression) in one transaction and lists the partitions it cleared; a reset of one stored partition's name clears that partition only; a partition the state does not hold is refused with `RIVET_CLI_EXPORT_UNKNOWN`, naming the partitions it does hold. `rivet state show` and `rivet state progression` list the partitions of the declared exports, and `rivet state accept` on a partitioned export or one of its partitions is refused with `RIVET_STATE_ACCEPT_PARTITIONED`. A mode `full` export with `partition_by`, a plain export and an export declared under the name of a would-be partition (`events__x` beside `events`) are unchanged. **What to do:** cursors that partitions already hold from earlier runs are cleared by the first reset after the upgrade; nothing in state needs a step. A reset made before the upgrade that cleared nothing is repeated once, with the destination emptied first if the full pass lands in it too.
