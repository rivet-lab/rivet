- **Behaviour change: a MongoDB `mode: cdc` run against a sharded cluster (mongos) no longer ends before it has read every write committed before it started.** Until now the run stopped on the first idle poll whose resume token was ahead of the token taken at open, and on mongos that token can come from a shard with nothing to say while another shard still holds events committed before the run began; the last write or two of the window (observed: the final delete) reached the destination one run late. **Now** the run stops only once the resume token has also reached the cluster time recorded when the stream was opened, so every write committed before the run started is in that run's output. A replica set behaves as before. On a sharded cluster with no traffic a run now waits for the shards' periodic no-op advance (observed 15 to 25 s), capped at 120 s: past that the run logs a WARN naming the cause, stops with exit 0 as it did before this change, and the writes still pending arrive on the next run from the checkpoint. **What to do:** nothing; the late write arrives in the same run, and a run that was already late delivered it on the next one, so no re-load or state reset is needed.
