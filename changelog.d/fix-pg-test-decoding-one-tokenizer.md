- **A PostgreSQL CDC change was dropped, or its cells shifted, when a schema, table or column name held the decoder's own separators.** The `test_decoding` reader cut each line at the first `: ` and read column names up to the first `[` and `]:`. A schema called `s: x` made every change of the table vanish: the slot advanced, the run exited 0 with `rows: 0`. A column called `a[b]:c` or `x]: y` was read under the wrong name, with the wrong value, or as a NULL key on a delete. **Now** one quote-aware reader cuts the line once: the relation at the operation, each quoted name at its closing quote. Every change is delivered under the name the source gave it, and a render-then-parse property with hostile names and values pins it. **What to do:** nothing for new changes. Rows a run already dropped are not in the slot any more; re-baseline the stream to recover them (the Recovery steps in docs/cheat-sheet.md, which the refusal also prints).
  **Changed stop:** a `bit` or `bit varying` column on a captured table now stops the run with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (exit 5) before the slot, the snapshot or any file is written; before, the run exited 0 and delivered the decoder's literal `B'110'` where the server's text is `110`. Batch refuses these columns with `RIVET_TYPE_UNSAFE_MAPPING`. **What to do:** change the column to text (`ALTER TABLE <schema>.<table> ALTER COLUMN <column> TYPE text USING <column>::text`), drop the export's slot on the source (`SELECT pg_drop_replication_slot('<slot>')`, the export's `cdc.slot`), then re-baseline the stream (the Recovery steps in docs/cheat-sheet.md, which the refusal also prints): changes already in the slot keep the bit type and refuse again until the slot is dropped, and the re-baseline creates it again at the current position with a snapshot of every row. Tables that hold no bit column are unaffected.
