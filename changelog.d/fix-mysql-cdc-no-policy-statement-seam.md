- **Behaviour change: a MySQL CDC export without `columns_from: grants` now stops on a TRUNCATE, DROP TABLE or statement-format write the server resolves to a captured table through its case fold, on `DROP DATABASE` / `DROP SCHEMA` of a database that holds a captured table, and on `ALTER TABLE ... TRUNCATE PARTITION`, `DROP PARTITION` or `EXCHANGE PARTITION` of a captured table.** Until now the statement reader compared names exactly, so on a server with `lower_case_table_names` other than 0 a `TRUNCATE TABLE SHOP.KINDS`, or a name spelled with the Kelvin sign (`U+212A` for `k`) or `U+0130` (for `i`), passed unseen, and the other two kinds of statement were not read at all. MySQL logs none of them as row events, so every row they removed stayed live in the destination while the run exited 0. **Now** the name is compared by the server's own fold (ASCII case, plus those two characters in the spelling the client character set gives them), on the bytes the statement was logged with, and the run stops before the statement with `RIVET_SOURCE_CDC_TRUNCATED` (exit 5), the checkpoint kept before it and nothing past it delivered. Under `columns_from: grants` the same statements now give `RIVET_SOURCE_CDC_TRUNCATED` where a partition operation gave `RIVET_SOURCE_CDC_UNDECODABLE` (both exit 5, same remedy), and `DROP DATABASE` of a captured database is stopped in the binlog as well, not only by the next run's column check. Tables whose names only resemble a captured one (another script, an accented letter) are not stopped on. **What to do:** nothing changes in the files or state written before the upgrade: no checkpoint or state format moved. A backlog that already holds such a statement stops at it on the first run after the upgrade, and the stop prints the way out: delete the checkpoint, move the export's destination files aside, clear its `cdc_snapshot` rows, keep `cdc.initial: snapshot`, then run again (verified by a live cell that follows it from a partition stop to a destination equal to the source). Empty a partition or a table with `DELETE` to avoid the stop.
