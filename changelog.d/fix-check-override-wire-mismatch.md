- **`rivet check` accepted a `columns:` override the run refuses (audit defect 11).** `check` and `check --type-report` printed "Looks good" and exited 0 for a declared type the source's value cannot be read as (an int4 column declared `string` on PostgreSQL, a text value declared `uuid` on MySQL, an INT column declared `string` on SQL Server, a TIMESTAMP with a time declared `date` on Oracle), and `rivet run` then ended with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1) on the first row. **Now** `check` reads the first row of each export that declares `columns:` through the run's own converter and ends with the same code and exit class before any run. **Changed stop (behaviour change):** a config that `check` used to bless and `run` refused now fails `check` with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1), at the cost of one extra one-row query per such export. **What to do:** remove the override, or CAST the column in the export's `query:` so the value matches the declared type. A zero-row source still passes `check`, as it passes the run.
