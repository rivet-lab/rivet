- **The remote-plaintext and cloud-endpoint gates now read a URL the way the HTTP client does.** They decided by the text of the URL, so `http:/host:8123`, `http:host:8123`, `ht<TAB>tp://host:8123` and `http://host\@127.0.0.1:8123` passed as non-`http://` or as loopback while the client sent the ClickHouse loader password and every row, the Slack webhook secret, the BigQuery OAuth bearer token or the uploaded rows to `host` in cleartext. **Behaviour change (changed stop):** these URLs are now refused: a ClickHouse `load.url`, a Slack `webhook_url` and `RIVET_BQ_API_ENDPOINT` with `RIVET_CONFIG_REMOTE_PLAINTEXT`, an S3/GCS/Azure `destination.endpoint` with `RIVET_CONFIG_DESTINATION_ENDPOINT_UNSAFE`; so is a plaintext-gated URL that does not parse (an empty `load.url`, `http://[::1`, a port above 65535, a comma host list), with `RIVET_CONFIG_REMOTE_PLAINTEXT` and a message that does not print the URL. The refusal names the host the client dials (lowercased, port omitted when it is the default 80, non-ASCII as punycode). A loopback the client normalises (`http://127.1`, `http://0x7f.1`) is now accepted, and `http://127.0.0.1\@host` is accepted because the client dials `127.0.0.1`. Exit codes are unchanged (1). **What to do:** write the URL as `https://host:port` (ClickHouse: `load.ca_file:` for a private CA; `load.allow_plaintext: true` on a path you already trust), or `http://127.0.0.1:port` for a local emulator; fix a URL the refusal says does not parse. State and tables written before the upgrade are not touched.
