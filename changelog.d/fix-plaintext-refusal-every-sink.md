- **The remote-plaintext refusal now covers every place rivet sends a secret, not only the source and state connections.** A ClickHouse `load.url`, a Slack `webhook_url` / `webhook_url_env` and the `RIVET_BQ_API_ENDPOINT` override accepted `http://` on any host, so the loader password and every loaded row, the webhook secret, or the BigQuery OAuth bearer token crossed the network unencrypted. **Behaviour change:** `rivet check`, `rivet run` and `rivet load` refuse such a ClickHouse `load.url`, and a literal Slack `webhook_url`, at config load with `RIVET_CONFIG_REMOTE_PLAINTEXT` (exit 1); a `webhook_url_env` that resolves to a remote `http://` URL is logged as `slack notification not sent` and the run is unaffected; a remote `http://` `RIVET_BQ_API_ENDPOINT` stops the BigQuery load with the same code. Loopback hosts (`localhost`, `127.0.0.0/8`, `::1`) stay allowed. **What to do:** use an `https://` URL (ClickHouse: `load.ca_file:` for a private CA); on a ClickHouse network path you already trust, write `load.allow_plaintext: true`; unset `RIVET_BQ_API_ENDPOINT` or point it at an `https://` or loopback endpoint. Slack and the BigQuery override have no opt-in. The code is new, so no earlier exit changes; `rivet validate` exits are unchanged.
