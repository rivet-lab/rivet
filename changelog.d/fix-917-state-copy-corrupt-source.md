- **`rivet state copy --to` names a corrupt SQLite source as corrupt (behaviour change; see #917).** Through the previous release a source file that is not a SQLite database was refused as `RIVET_STATE_COPY_SOURCE_EMPTY` ("holds no state to copy"), which sent the operator to name another file while the one named was damaged. **Now** it is refused as `RIVET_STATE_FILE_CORRUPT` (same exit 1) with the remedy to restore it from a backup or name the file that holds the state; an empty, missing or table-less source keeps `RIVET_STATE_COPY_SOURCE_EMPTY`. No state or table written before the upgrade changes: the copy refuses before it reads or writes any row. **What to do:** restore the file from a backup, or point the copy at the config whose `.rivet_state.db` holds the state.
