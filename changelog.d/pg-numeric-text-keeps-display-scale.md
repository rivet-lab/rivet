- **A PostgreSQL `numeric` delivered as text dropped its display scale: `1.50` landed as `1.5`, `0.00` as `0`, `1000.000` as `1000`.** Behaviour change. A column read through the binary wire as text, that is a `numeric` under a `columns:` string override (bare or `NUMERIC(p,s)`) and the same value in a CDC change, was rebuilt with the digits' natural scale, while the server's own text carries the column's scale; exit 0, no warning. **Now** the text is the server's text for the same value: `1.50`, `0.00`, `1000.000`, `NaN` unchanged. A `numeric` read as a decimal, and a bare `numeric` with no override (already the server's text), keep their bytes; no other engine is affected. Rows and tables written before the upgrade keep the shortened text. **What to do:** re-export the affected tables (a full export, or an incremental load deduplicated on the key) when downstream code compares the text byte for byte or parses its scale; nothing otherwise.
