- **A PostgreSQL `numeric` delivered as text dropped its display scale: `1.50` landed as `1.5`, `0.00` as `0`, `1000.000` as `1000`.** Behaviour change. A `numeric` read through the binary wire as text, that is a `numeric` under a `columns:` string override (bare or `NUMERIC(p,s)`), was rebuilt at the natural scale of its digits while the server's text carries the column's scale; exit 0, no warning. **Now** the text is the server's text for the same value: `1.50`, `0.00`, `1000.000`, `NaN` unchanged. A `numeric` read as a decimal, and a bare `numeric` with no override (already the server's text), keep their bytes, and so does PostgreSQL CDC, which already delivered the server's text in both the snapshot and the stream leg; no other engine is affected. Rows and tables written before the upgrade keep the shortened text, so a key column holding such a text (`10` before, `10.0` after) is two keys downstream. **What to do:** re-export the affected tables (a full export, or an incremental load deduplicated on the key) when downstream code compares the text or parses its scale; nothing otherwise.
