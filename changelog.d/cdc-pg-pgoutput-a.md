- **A PostgreSQL CDC export pointed at a slot created with another output plugin failed on the first line it could not parse.** Behaviour change. A `cdc.slot` that already existed with the `pgoutput` or any non-`test_decoding` plugin was read as `test_decoding` text and stopped with an uncoded parse error. **Now** the open stops before any read with `RIVET_SOURCE_CDC_PREREQUISITE` (exit 5) naming the slot and its plugin; a `test_decoding` slot, the only kind rivet creates, is read as before. `cdc.publication` is accepted on PostgreSQL exports (default: the slot name), refused on other sources, and refused when two exports resolve to the same name; the stream does not read it yet. Existing slots, checkpoints and tables are unchanged. **What to do:** nothing for a slot rivet created; for a slot another tool created, drop it (`SELECT pg_drop_replication_slot('<slot>')`) and re-baseline, or set `cdc.slot` to a new name.
