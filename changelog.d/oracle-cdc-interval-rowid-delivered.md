- **Oracle CDC now captures `INTERVAL YEAR TO MONTH`, `INTERVAL DAY TO SECOND` and `ROWID` columns as the text batch delivers (behaviour change).** A table with such a column used to be refused when the stream opened, with `RIVET_SOURCE_CDC_TABLE_UNSUPPORTED` (exit 1) naming the column. **Now** the snapshot and the stream write the same ISO 8601 duration text for an interval (`P999999999Y11M`, `P-1DT-2H-3M-4.123456S`) and the 18-character form for a `ROWID`, in one `Utf8` column, through the renderers batch uses. An `INTERVAL DAY TO SECOND(7..9)` value with a sub-microsecond fraction stops the run with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) naming the column, as batch does; the remedy is the same: select `TO_CHAR(col) AS col`. The refusal text for a table LogMiner cannot mine now lists the supported kinds with the three new ones and no longer names them. `CLOB`, `NCLOB`, `BLOB`, `LONG`, `LONG RAW`, `XMLTYPE`, `JSON`, `BOOLEAN`, `VECTOR` and `UROWID` stay refused by the same code: LogMiner returns no value for them, or an empty one for `UROWID`. Tables and state written before the upgrade are untouched: a stream that was refused on such a column is run again after the upgrade, with no state migration. **What to do:** nothing for a table that was captured; for a refused table, re-run the export after the upgrade.
