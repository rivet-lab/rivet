- **PostgreSQL CDC now delivers `bit`, `bit varying` and arrays of types with no Arrow mapping as the server's text, as batch does, and an Oracle CDC run that meets NUMBER infinity stops with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (behaviour change).** A PostgreSQL CDC run used to stop with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (exit 5) on a `bit` or `bit varying` column, and on an `inet[]`, `cidr[]`, `macaddr[]`, `point[]`, `int4range[]`, `tstzrange[]` or `bit(n)[]` column, where batch delivers the server's text. **Now** the stream writes `110` for `B'110'` and the server's array literal for such an array, in one text column; a stream that was refused on such a column is run again after the upgrade; dropping the slot and changing the column to text, as the earlier refusal advised, stays valid but is no longer needed. An Oracle CDC run that read NUMBER infinity (LogMiner prints `~` or `-~`) stopped under `RIVET_SOURCE_CDC_CELL_UNSUPPORTED`; it is now `RIVET_SOURCE_VALUE_UNREPRESENTABLE`, the code batch gives the same value (exit class and remedy text changed; the value is still never delivered).
