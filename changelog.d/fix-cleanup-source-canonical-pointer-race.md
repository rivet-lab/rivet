- **`cleanup_source` no longer removes the `manifest.json` and `_SUCCESS` of a run that committed while the load was running.** The load read which run a directory's canonical `manifest.json` names before the warehouse jobs, then removed `manifest.json` and `_SUCCESS` after them without looking again. An extract that committed in between (its canonical manifest and `_SUCCESS` are written at the end of the run) lost both, so the directory read as not whole (0.32.2 and earlier, BigQuery, Snowflake and ClickHouse). **Now** each of the two is removed only if, at the moment of its own delete, the canonical manifest still names a run this load cleaned; otherwise it stays. The window shrinks to the single round trip between that read and its delete: GCS offers no conditional delete through rivet's store, so it is not zero, and the lease between a load and an extract that would close it is the open part of P9 in `dev/open-issues.md`. **What to do:** nothing; a directory that already lost its markers gets both written again by the next committed run of that export.
