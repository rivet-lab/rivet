- **A table with a composite primary key could not be exported in bounded pages (#792).** `chunk_by_key` took one column, so a primary key such as `uuid` + `varchar` left `mode: full` with one long read transaction as the only choice. **Now** `chunk_by_key: [id, kind]` names the primary key's columns in key order. Rivet pages by the key tuple, and `chunk_checkpoint: true` resumes a crashed run from the last stored tuple. This works on PostgreSQL, MySQL, SQL Server and Oracle. A list that is not the primary key in order, or that has a column of a type the cursor cannot read, stops the plan with `RIVET_PLAN_CHUNK_KEY_UNUSABLE`. A composite key runs sequentially: `parallel: N` and `keyset_incremental` are refused with it for now. **What to do:** nothing for existing configs; a single-column `chunk_by_key` is unchanged.
