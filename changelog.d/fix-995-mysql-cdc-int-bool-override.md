- **A MySQL stream delivered every non-zero value of an integer column declared `bool` as `true` (#995).** Behaviour change. A `columns: { c: bool }` override over a SMALLINT, MEDIUMINT, INT, BIGINT, BIGINT UNSIGNED or TINYINT other than `TINYINT(1)` was read by a CDC run as `value != 0`, so 2, 300 or 18446744073709551615 became `true` with exit 0 where the batch export already refused any value outside 0 and 1. **Now** the stream refuses such a value `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) naming the column, the value and its row, before any part of that batch is written and before the checkpoint moves; 0, 1 and NULL are delivered as before; the same refusal now applies on PostgreSQL, SQL Server and Oracle streams. Parts and tables written before the upgrade are untouched; a stream that already delivered a non-flag value as `true` keeps those rows. **What to do:** remove the `bool` override for the column (or correct the values to 0 and 1), then follow the re-baseline step the refusal prints.
