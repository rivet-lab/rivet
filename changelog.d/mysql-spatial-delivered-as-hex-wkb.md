- **A MySQL spatial column (`GEOMETRY`, `POINT`, `LINESTRING`, `POLYGON`, `MULTIPOINT`, `GEOMETRYCOLLECTION`) is delivered as the lowercase hex of its standard WKB, in batch and CDC, instead of being refused with `RIVET_TYPE_UNSAFE_MAPPING`.** Behaviour change. Before, a batch export, `rivet check` and a CDC snapshot of such a column stopped before any write. **Now** the column is a `Utf8` column labelled `rivet.text_form: hex_wkb`, equal to `LOWER(HEX(ST_AsBinary(col)))`; a warehouse recovers the geometry with BigQuery `ST_GEOGFROMWKB`, Snowflake `TO_GEOMETRY` or ClickHouse `readWKB*(unhex(x))` (25.8 or later). WKB holds no SRID, and a geographic SRS stores its axes in the other order than `ST_AsBinary` writes them, so a value whose SRID is not 0 is refused `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) naming the column and its SRID, before a part is written and before the checkpoint moves; it is never delivered without its SRS. A column declared `string` or `binary` in `columns:` is unchanged. Tables and state written before the upgrade are untouched: a config that ran has no spatial column, since every such run was refused. **What to do:** for an SRID other than 0 declare the column `binary` in `columns:` to carry MySQL's internal bytes (4-byte little-endian SRID, then WKB), or in a batch export select `ST_AsBinary(col)` and `ST_SRID(col)` in the `query:`; in a CDC stream declare it `binary` or leave the column out of the capture.
