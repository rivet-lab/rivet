- **An Oracle `NUMBER` held as exact text carried no label saying so (ADR-0038 CP5).** A bare `NUMBER`, a `FLOAT`, and a `NUMBER` whose scale or negative scale no 38-digit decimal holds were written as plain decimal text in a `Utf8` column, in a batch part and in a CDC snapshot, stream and final image alike, but without the `rivet.text_form` field metadata that marks a canonical text (ADR-0038 CP2), so nothing downstream could tell the column was a number. **Now** those columns carry `rivet.text_form = decimal_plain`, `rivet check` lists them as `logical_string` (accepted by `--strict`), and the values are byte-for-byte the text they were. **Behaviour change.** The column stays `Utf8`, the stored schema baseline does not change, and the load spec recorded for the column changes only its fidelity word (`exact` to `logical_string`), so existing tables, state and `rivet load` targets keep working; the new field metadata appears in parts written after the upgrade. **What to do:** nothing; an explicit `columns:` override of the column is unchanged and carries no label.
