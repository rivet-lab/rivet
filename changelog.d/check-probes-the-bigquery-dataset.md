- **`rivet check` refuses a BigQuery `load:` block whose dataset the project does not hold, where it exited 0 and `rivet load` then stopped `RIVET_LOAD_WAREHOUSE_REJECTED` (behaviour change).** Before, `rivet check` never contacted the warehouse: a config whose `load.dataset` did not exist passed `check` and failed at the first job of `rivet load` with `Not found: Dataset`. **Now** `check` asks BigQuery (`datasets.get`, once per distinct destination credential of the checked exports) and stops with the same code, `RIVET_LOAD_WAREHOUSE_REJECTED` (exit 1), naming the dataset and the remedy. An answer that cannot say (no credential, 401, 403, a transport failure) is a warning, never a refusal, so a machine that may run `check` but not read the warehouse still passes it; a config with no `load:` block, or a Snowflake or ClickHouse target, asks the warehouse nothing (those two are still not read by `check`). Nothing written before the upgrade changes: no state, file or table is read or written by the new question. **What to do:** create the dataset in the location of the staging bucket (`bq mk -d <project>:<dataset>`) and re-run `rivet check`; a dataset that exists passes as before.
