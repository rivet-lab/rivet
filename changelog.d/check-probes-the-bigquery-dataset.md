- **`rivet check` refuses a `load:` block whose BigQuery dataset, ClickHouse database, or Snowflake database or schema the warehouse does not show, where it exited 0 and `rivet load` then stopped at its first statement (behaviour change).** Before, `rivet check` never contacted the warehouse: a config whose `load:` named a missing place passed `check` and failed in `rivet load` (`RIVET_LOAD_WAREHOUSE_REJECTED` with `Not found: Dataset` on BigQuery, `RIVET_LOAD_WAREHOUSE_OBJECT_NOT_FOUND` with `UNKNOWN_DATABASE` on ClickHouse, `RIVET_LOAD_WAREHOUSE_REJECTED` on Snowflake). **Now** `check` asks the warehouse read-only (BigQuery `datasets.get` once per distinct destination credential of the checked exports; ClickHouse one `system.databases` count with the load's user; Snowflake `SHOW DATABASES` and `SHOW SCHEMAS` with the load's login, no warehouse resumed) and stops, exit 1, with the code `rivet load` stops with, naming the place and the remedy. An answer that cannot say (no credential, 401, 403, a transport failure, no answer within 30 seconds) is a warning on stderr with exit 0 and no code, never a refusal, so a machine that may run `check` but not read the warehouse still passes it, and `rivet load` is the first to see an unreachable warehouse; a config with no `load:` block asks the warehouse nothing. Nothing written before the upgrade changes: no state, file or table is read or written by the new question. Known limit: a ClickHouse database that exists but on which the load's user holds no grant is hidden by `system.databases`, so `check` refuses it as not visible with `RIVET_LOAD_WAREHOUSE_OBJECT_NOT_FOUND` while `rivet load` stops with `RIVET_LOAD_WAREHOUSE_REJECTED` (server `ACCESS_DENIED`); the exit is 1 in both and the remedy (grant the user access) is the same. The code `check` gives equals the code `rivet load` gives for a missing place on BigQuery and ClickHouse (ClickHouse measured by hand against the server, `UNKNOWN_DATABASE` on HTTP 404); on Snowflake it is the code of a statement error (HTTP 422) and is not yet compared against a live `rivet load`. **What to do:** create the place (`bq mk -d <project>:<dataset>`, `CREATE DATABASE <database>`, `CREATE SCHEMA <database>.<schema>`) and grant the load's user or role access to it, then re-run `rivet check`; a place that exists and is visible passes as before.
