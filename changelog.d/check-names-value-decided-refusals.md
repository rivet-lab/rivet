- **`rivet check` says which refusals it cannot decide.** Before, `rivet check` exited 0 on an export whose run then refused a value with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` or `RIVET_LOAD_VALUE_OUT_OF_TARGET_RANGE`, with no hint that check reads no values and so cannot see them. **Now** check prints `note[values-unread]: rivet check reads no values; a run may still refuse a value with RIVET_SOURCE_VALUE_UNREPRESENTABLE, RIVET_LOAD_VALUE_OUT_OF_TARGET_RANGE` on stderr; its exit code and stdout are unchanged. `docs/reference/errors.md` lists these codes under "Decided by a value". **What to do:** nothing; a script that parses check's stderr should skip lines starting with `note[`.
- **SQL Server and Oracle refuse a value an override cannot hold with the value code, as MySQL and PostgreSQL do.** Before, a `columns:` override refused by a value it could not hold (an Oracle `DATE` or `TIMESTAMP` with a time of day under `date`, an Oracle `RAW` of the wrong length under `uuid`, SQL Server text that is not a uuid under `uuid`, a SQL Server decimal whose digits a narrower scale would drop) stopped with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1, a usage error), while the same case on MySQL and PostgreSQL stopped with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5, a refusal). **Now** all four engines use `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) for these; `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` stays for an override the reader cannot build at all. **What to do:** a script that matched `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` or exit 1 for these cases must match the new code and exit 5.
