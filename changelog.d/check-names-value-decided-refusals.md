- **`rivet check` says which refusals a value it did not read can still raise.** Before, `rivet check` exited 0 on an export whose run then refused a value with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` or `RIVET_LOAD_VALUE_OUT_OF_TARGET_RANGE`, with no hint that check reads at most the first row of an export that declares `columns:`. **Now** check prints `note[values-unread]: rivet check reads at most the first row of an export that declares `columns:`; a run may still refuse a value it did not read with RIVET_SOURCE_VALUE_UNREPRESENTABLE, RIVET_LOAD_VALUE_OUT_OF_TARGET_RANGE` on stderr; its exit code and stdout are unchanged. `docs/reference/errors.md` lists these codes under "Decided by a value". **What to do:** nothing; a script that parses check's stderr should skip lines starting with `note[`.
- **Behaviour change, exit 1 to exit 5: a value an override cannot hold is refused with the value code on SQL Server, Oracle, and on a CDC snapshot and stream, as MySQL and PostgreSQL do.** Before, a `columns:` override refused by a value it could not hold (an Oracle `DATE` or `TIMESTAMP` with a time of day under `date`, an Oracle `RAW` of the wrong length under `uuid`, SQL Server text that is not a uuid under `uuid`, a SQL Server decimal whose digits a narrower scale would drop; and on a CDC snapshot or stream, any cell of a readable wire type the declared type could not hold, such as fractional text under an integer override) stopped with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1, a usage error), while the same case on MySQL and PostgreSQL batch stopped with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5, a refusal); an Oracle CDC export gave exit 5 on its snapshot leg and exit 1 on its stream leg for the same value. **Now** every engine and every leg uses `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) for these; `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1) stays for an override the reader cannot build and for a value of a wire type the declared type cannot read. No state or table written before the upgrade changes: both codes stop the run before any part is written or any checkpoint moves. **What to do:** a script that matched `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` or exit 1 for these cases must match `RIVET_SOURCE_VALUE_UNREPRESENTABLE` and exit 5; a scheduler that retries on exit 1 and stops on 5 now stops, which is right, since the value will not change on retry.
