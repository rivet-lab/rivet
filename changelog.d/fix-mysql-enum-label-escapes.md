- **A MySQL CDC stream delivered an ENUM or SET label with a backslash, a line feed, a carriage return or a NUL as the catalog writes it, not as it is stored.** rivet maps the binlog's ENUM index and SET bitmask to a label through the column's `COLUMN_TYPE` text, and reversed only the doubled quote of the escaping MySQL applies there. A label such as `C:\temp` reached the destination as `C:\\temp`, one holding a line feed as `a\nb` (a backslash and an `n`), while the snapshot of the same row held the stored label, exit 0. **Now** every escape MySQL writes (`\\`, `\n`, `\r`, `\0`, `''`) is reversed, and a label MySQL writes as a hex literal `x'..'` is read as the text it spells. **Changed stop:** an ENUM or SET column whose label is a hex literal that is not UTF-8 text is refused with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (exit 5) when a row of it is decoded, where it delivered the literal's digits before. **What to do:** follow the refusal: leave that column out of the capture, then re-baseline the stream as `docs/reference/errors.md` lists for this code. Rows a CDC run delivered before the upgrade keep the doubled escapes in those columns: re-read the affected table with a snapshot (`initial: snapshot` on a new checkpoint, or a full export) to replace them; rows delivered by a snapshot or a batch export were never affected.
