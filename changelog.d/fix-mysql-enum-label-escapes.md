- **A MySQL CDC stream delivered an ENUM or SET label with a backslash, a line feed, a carriage return or a NUL as the catalog writes it, not as it is stored.** rivet maps the binlog's ENUM index and SET bitmask to a label through the column's `COLUMN_TYPE` text, and reversed only the doubled quote of the escaping MySQL applies there. A label such as `C:\temp` reached the destination as `C:\\temp`, one holding a line feed as `a\nb` (a backslash and an `n`), while the snapshot of the same row held the stored label, exit 0. **Now** every escape MySQL writes (`\\`, `\n`, `\r`, `\0`, `''`) is reversed. **Changed stop:** an ENUM column with a label that MySQL writes as a hex literal `x'..'` (a binary-character-set label holding bytes that are not utf8mb3 text) is refused with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (exit 5) when a row of it is decoded, with or without a `columns:` override of that column (an override raised `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH`, exit 1, telling the operator to drop the override, as did a stream index past the column's labels), where it delivered the literal's digits as the label before: MySQL writes those digits without zero padding, so the label's bytes cannot be recovered from `COLUMN_TYPE`. **What to do:** follow the refusal: leave that column out of the capture, then re-baseline the stream as `docs/reference/errors.md` lists for this code. Rows a CDC run delivered before the upgrade keep the doubled escapes in those columns: re-read the affected table with a snapshot (`initial: snapshot` on a new checkpoint, or a full export) to replace them; rows delivered by a snapshot or a batch export were never affected.
