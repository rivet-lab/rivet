- **A composite-key export could only read one page at a time (#792).** `chunk_by_key: [id, kind]` refused `parallel: N`, so a very large table with a composite primary key was read by a single worker. **Now** `parallel: N` splits the table into ranges of the key's first column; each worker reads its range page by page on the whole key tuple, and every row of one first-column value stays in one range. With `chunk_checkpoint: true` a crashed run resumes only the ranges that had not finished. This works on PostgreSQL, MySQL, SQL Server and Oracle; `keyset_incremental` stays refused with a composite key. **What to do:** add `parallel: N` to a composite `chunk_by_key` export to read it with N workers.
