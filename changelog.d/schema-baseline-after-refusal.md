- **Behaviour change: a run that is refused no longer replaces the stored schema baseline of its export.** Before, `on_schema_drift: warn` (the default) and `continue` wrote the schema a run observed into `export_schema` at the drift check, before the quality gate, a coded stop (an Oracle `RIVET_SOURCE_CDC_UNDECODABLE`, a `load.pk` naming a missing column) or any later failure could refuse the run; the next run then compared against a schema the refused run never delivered and reported no drift, so the change was warned about once and lost. **Now** a batch run (single, chunked, keyset, incremental) and a CDC run (PostgreSQL, MySQL, SQL Server, Oracle, MongoDB) hold the observed schema and store it only when the run ends clean; a refused run leaves `export_schema` as it found it, and the retry warns about the same drift again and stores it once it succeeds. `on_schema_drift: fail` refuses with the same text and exit code as before, and the warning text is unchanged. A baseline written before the upgrade, including one a refused run had already rewritten, is read as stored: the file format is unchanged and nothing is migrated. A first run that fails still records its first baseline (the `export_schema` row of a never-succeeded export, a known defect). **What to do:** nothing; a script that read `export_schema` after a refused run to find the observed schema must read it after the run that succeeds.
