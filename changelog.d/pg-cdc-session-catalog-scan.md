- **A PostgreSQL CDC session no longer reads the built-in array types of `pg_type` when it opens (behaviour change).** Each reader session read every array type of the server's type catalog, about 1800 source tuples, whatever tables the export captures, so a run that polls often paid that on every session. **Now** the open reads the domains and the user-defined array types only (one per table, enum, composite, range and domain of the database), and each built-in array type is asked of the catalog once per session, the first time a change carries it. A database whose user types are few opens on about 1400 tuples where it used to open on about 3100; the open now grows with the number of user-defined types, and a session that meets a built-in array type pays one catalog lookup for it. **What a stream delivers is the same as before** for every array column the open knew: each label is decided as the open decided it, so a type, schema or table renamed, a type moved to another schema, a type dropped or a search path with same-named types after the open leave the delivered lists and server text as they were. When a user-defined type bears the name of a built-in one, the open reads every array type as before. A label the catalog does not hold is asked once per session and stays a list, as before. No state, checkpoint or slot is touched, so nothing needs repair after the upgrade; **what to do:** nothing.
