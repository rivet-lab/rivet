- **A PostgreSQL CDC session no longer reads every array type of `pg_type` when it opens (behaviour change).** Each reader session read all array types of the server's type catalog, about 1800 source tuples, whatever tables the export captures, so a run that polls often paid that on every session. **Now** the session asks the catalog about an array type by its name, the first time a captured table's change carries it; a table without arrays costs the source nothing more than the domains read. What a stream delivers is unchanged: the same array columns arrive as the same lists or server text, including an array column added while a continuous run is open and a row whose column was dropped, retyped or whose table was renamed before the row was read. One difference remains, for a custom array type of a composite or range kind created or dropped while a continuous run is open: it is now resolved as of the read, where the open used to decide. No state, checkpoint or slot is touched, so nothing needs repair after the upgrade.
