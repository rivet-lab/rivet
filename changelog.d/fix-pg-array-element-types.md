- **Behaviour change: PostgreSQL `date[]`, `timestamp[]`, `timestamptz[]`, `time[]`, `uuid[]` and `bytea[]` columns are delivered as native lists in the batch export and in CDC.** The batch export refused these arrays ("temporal/uuid/bytea array elements are not yet supported"), and a CDC run carried them as the server's own text (`server_text`, a `{...}` literal in a string column). Both now write an Arrow list of the element type (`uuid[]` with the `arrow.uuid` item, so a reader sees native UUIDs), and a ClickHouse load graded against the source reads them back as `Array(Date32)`, `Array(DateTime64(6, 'UTC'))`, `Array(Decimal(18, 6))` (time of day in seconds), `Array(FixedString(16))` (uuid bytes) and `Array(String)` (bytea). `numeric[]`, `json[]` and `interval[]` are unchanged (the batch export still refuses them; CDC still carries `numeric[]` as text), and a multi-dimensional array is still refused. A ClickHouse array cannot be NULL, so a NULL `date[]`, `time[]`, `timestamp[]`, `timestamptz[]`, `uuid[]` or `bytea[]` cell loads as `[]`, as a NULL `text[]` already did. The ClickHouse load also checks each timestamp list by its own Parquet leaf instead of the leaf name `item`, so a table with two list columns no longer reads the wrong column's statistics. The refusal for an array that does not decode now also names the `infinity`, `-infinity` and `24:00:00` elements of a date, time or timestamp array and the remedy (map them to a real bound in the query). **Behaviour change, checked on a live run (old binary, then this one):** a CDC export that streams one of these columns writes its first part after the upgrade with the new type, and `rivet run` logs one `schema changed! type changed: <col> (Utf8 -> List(...))` warning and exits 0; the next run with no new changes is quiet. A ClickHouse table is declared `Array(...)` from the recorded type, so a part written by the old version (text in a string column) never loaded and still does not: the load stops with `Array does not start with '[' character`, the same stop the old version gave. Parts written after the upgrade load and read back equal to the source. Nothing in state or in a loaded table changes shape.
