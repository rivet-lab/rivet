- **Behaviour change: `source.columns_from: grants` is accepted on Oracle sources (it was refused at config load) (refs #714).** Oracle has no column-level SELECT privilege (`GRANT SELECT (col)` is ORA-00969), so the readable set of a table is every column the account may `SELECT *` (INVISIBLE columns are left out, as `SELECT *` leaves them) or none: a table the account may not read is refused with `RIVET_SOURCE_COLUMNS_UNREADABLE` and the remedy "GRANT SELECT on the table to the account" instead of a raw ORA-41900, an unreadable key is refused naming `load.pk`, and `rivet check` and the start of a change-stream run state that the policy is data minimisation, not access control (the capture account's LogMiner views and the redo carry every column). Remedy for an existing Oracle config that wants the old refusal: remove `columns_from:` from `source:`; configs without the key are unchanged.
