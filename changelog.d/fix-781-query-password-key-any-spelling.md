- **A URL query password under a compound key reached logs, summaries and the journal in clear (#781).** The redactor masked a query pair only for a key named `password` or ending in `_password`/`-password`, while the keyword/value path masks every key ending in `password`, `passwd` or `pwd`. So `postgres://u:p@h/db?sslmode=require&sslpassword=…&SSLPassword=…` kept both values, and so did `db.password`, `x-passwd` and `MYSQL_PWD` in a query. **Now** one rule governs both paths: every key ending in `password`, `passwd` or `pwd`, in any case, is masked in a URL query. **Changed output:** a query key that merely ends in one of those words (for example `?mypwd=…`) is now shown as `***` in logs, `summary.json` and the journal; nothing delivered changes. **What to do:** nothing; rotate a password that an earlier version may have written to a log or summary under such a key.
