- **A `columns:` override the source cannot convert was written as NULL, ignored, or stopped with no code.** Behaviour change. Since the override feature, a pair such as a MySQL text column declared `int64` with a non-numeric value wrote NULL, a MongoDB `_id`/`document` override was silently ignored, and many pairs stopped with an uncoded driver error, while `rivet check` passed the same config. **Now** one table per engine decides, before any row is read, whether the source converts each overridden column to its declared type; `rivet check` and `rivet run` both read it, on every mode including `cdc` and on MongoDB, and an unconverted pair stops with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH` (exit 1) naming the column, its native type and the declared type. A value the converter cannot represent in a pair it does convert stops with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` instead of NULL. Files and tables written before the upgrade are unchanged; a config that relied on the old NULL or on an ignored MongoDB override now stops at `check`. **What to do:** run `rivet check`; for each refused column remove the override, or CAST the column to the declared type in the export's `query:`.
