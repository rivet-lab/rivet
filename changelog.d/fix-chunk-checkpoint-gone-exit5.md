- **A chunked run that lost its checkpoint rows ended exit 1, or exit 0 with a partial delivery.** When the `chunk_run` or `chunk_task` rows of a running export were removed (a `state reset` on a live run, a hand delete), the run-end check counted what it still saw. A deletion still open on a Postgres state made the claim skip the locked rows and the count read the old ones, so the run ended `RIVET_RUN_UNITS_FAILED` (exit 1) with a `--resume` hint; when only the tasks vanished and the run row stayed, nothing was pending and the run finalized with exit 0 and a partial delivery. **Now** the run end reads the run's rows behind any open writer and compares them with the planned chunk count. **Changed stop:** a chunked run that loses its checkpoint rows ends `RIVET_STATE_CHUNK_CHECKPOINT_GONE` (exit 5), not exit 1 and not exit 0. **What to do:** run the export again; it starts a new chunk run. Nothing in the state or in earlier tables changes shape, and a chunk that genuinely failed still ends exit 1 with the `--resume` hint.
