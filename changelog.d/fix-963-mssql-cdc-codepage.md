- **Behaviour change: SQL Server CDC refuses a captured `char`/`varchar`/`text` column whose codepage differs from the database's.** The capture job stores such a column in the database codepage, so a character outside it (Cyrillic in a Latin1 database, any non-ASCII in a UTF8-collated column) reached the warehouse as `?` with exit 0. **Now** `rivet run` stops at open with `SOURCE_CDC_PREREQUISITE`, naming each `schema.table.column`; `nvarchar` columns and columns sharing the database codepage are unaffected. **What to do:** change the column to `nvarchar` (or give it the database collation), re-enable the capture instance, and run again; rows already delivered as `?` stay in the warehouse and must be re-read with a fresh snapshot.
