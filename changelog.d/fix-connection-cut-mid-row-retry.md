- **A MySQL or PostgreSQL connection dropped while a row was being read ended the run instead of being retried.** The driver reports a peer that closes the socket in the middle of a packet as a codec error (MySQL) or a plain connection error (PostgreSQL) with `bytes remaining on stream`, which the retry classifier did not read as a lost connection: the export exited 1 with 0 rows and `retries` 0, while a cut between two queries retried. **Now** a cut inside a row is a lost connection on both engines and the export retries on a fresh connection, exactly as it does for a cut between queries. Genuine MySQL protocol errors (oversized or out-of-sync packets, a bad compressed header) keep their class. No state or table written before the upgrade changes.
