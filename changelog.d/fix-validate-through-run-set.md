- **`rivet validate` of a `partition_by` export verified nothing and exited 0.** `validate` took the declared export list, so a `partition_by` export was read at the literal `{partition}` prefix, found no manifest, and passed as a legacy run even with partition directories deleted. `plan`, `check`, `reconcile`, `repair`, `state accept`, the dispatch batch plans and `load` check selected their exports through their own copies of the same lookup. **Now** every one of them takes its exports from the run set `rivet run` uses, and `validate` verifies every `<parent>__<bucket>` partition directory. **Behaviour change:** `validate` of a `partition_by` export now reads the source once for the partition list (the same min / max and NULL-count read `rivet run` makes), so it is no longer source-free for that export; a partition the source holds and the destination does not fails with `RIVET_VERIFY_PARTITION_NOT_DELIVERED` (exit 3), and a source that cannot be read is refused with `RIVET_SOURCE_PROBE_UNREADABLE`. **What to do:** re-deliver a missing partition with `rivet run --export <name>`; to verify one partition directory without the source, run `rivet validate --export <name> --prefix <partition directory>`. A source with no rows exits 0 with "partition_by found no rows in the source: no partition to validate". Exports without `partition_by` are unchanged.
