- **Security**: `rivet validate` (and the `--validate` gate of a run) masks the credentials the object store put in its own error text before it writes a failure's detail, so an Azure SAS token spelled without `sig=` no longer reaches the `--output` file or the terminal through the OpenDAL error's `uri:` field when the manifest, `_SUCCESS` marker or listing read fails. Behaviour change: the detail line of a `manifest read error`, `_SUCCESS read error` or `destination listing error` now shows `***` where the token stood; nothing persisted before the upgrade changes, and the exit code and error code are the same.
