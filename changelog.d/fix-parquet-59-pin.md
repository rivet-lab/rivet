- **arrow and parquet stay at exactly 59.0.0, the versions 0.32.2 shipped.** The unreleased move to 60 (#702) changed the bytes of the Parquet files written for the same rows (column pages ended on a different row grid for nullable columns without NULLs) and, on wide fixed-width columns (Oracle `NUMBER(19)`, `decimal(p>18)`, `uuid`) under `target_row_group_mb`, made the writer keep memory proportional to the row count. **Now** `arrow`, `arrow-schema` and `parquet` are pinned `=59.0.0`, the write-call splitting added for 60 (#704) is gone, and a test pins the bytes of ten writer shapes to the digests the v0.32.2 tag produced. The files are byte-identical to 0.32.2 and writer memory is flat as in 0.32.2. Parquet ZSTD pages go through zstd 0.13 again; `.cargo/audit.toml` records why none of the zstd advisories is reachable there. **What to do:** nothing; a release that changes these bytes on purpose regenerates the digests (`dev/pytools/parquet_golden.py`) and marks the CHANGELOG entry as a byte change.
