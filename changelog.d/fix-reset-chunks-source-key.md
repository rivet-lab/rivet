- **`state reset-chunks` removed the chunk checkpoint of another source, and of a live run (behaviour change).** `reset-chunks` and `reset-chunks --stuck-checkpoints` took the run lease on the config's source, which is empty when the source does not resolve, and then deleted every checkpoint of the export name whatever source wrote it. With `url_env` unset, or from a config of the same export name on another source, a reset passed the lease check of a live checkpointed run and removed its checkpoint; that run ended with `RIVET_STATE_CHUNK_CHECKPOINT_GONE` (exit 5). **Now** both forms remove only the checkpoints of this config's source (plus those from a release before the source was recorded, which belong to no source, and those recorded under another spelling of the same source, such as the default port left out, which are re-keyed onto it first so no resume anchor is left behind), and take the lease on that source. **Changed stop:** `reset-chunks` and `--stuck-checkpoints` now refuse a source that does not resolve with its coded error (`RIVET_CONFIG_SECRET_UNSET` or `RIVET_CONFIG_SOURCE_CONNECTION_INVALID`, exit 1) and remove nothing, even when no checkpoint is stuck; `--stuck-checkpoints` no longer lists, or clears, the exports of another source. **What to do:** set the variable `url_env` names (or fix the source URL) and repeat the command; to abandon a checkpoint written by another config, run `reset-chunks` from that config.
