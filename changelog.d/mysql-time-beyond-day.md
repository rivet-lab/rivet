- **Behaviour change: a MySQL `TIME` column is delivered as `Utf8` text (`[-]hh:mm:ss.ffffff`, `rivet.text_form: time_beyond_day`), where it was `Time64(µs)`, so a duration of 24 hours or more, or a negative one, is kept instead of stopping the run.** A MySQL `TIME` is a signed duration from `-838:59:59` to `838:59:59`; a value outside `00:00:00..24:00:00` (for example `25:30:15`, `838:59:59` or `-00:00:01`) was refused `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) by batch and CDC, because `Time64(µs)` is a time of day. **Now** every `TIME` value is delivered, batch and CDC, as text with the sign, at least two hour digits and six fraction digits (`25:30:15.000000`, `-838:59:59.000000`, `14:30:00.123456`). A `columns: { <column>: text }` override on a `TIME` is refused as before. Parts and warehouse tables written before the upgrade keep `Time64(µs)`; the first run after it reports the column once as `type changed: <column> (Time64(Microsecond) → Utf8)` under the default `on_schema_drift: warn`, and stops under `on_schema_drift: fail`. **What to do:** under `on_schema_drift: fail`, run once with `on_schema_drift: warn` (the run reports the retype and stores the new schema, the next run under `fail` passes); a warehouse table that already holds the `Time64` column is loaded into a new table or dropped and recreated, as for any column retype.
