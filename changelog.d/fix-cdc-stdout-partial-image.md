- **Behaviour change: `rivet cdc` without `--output` refuses a change with a partial row image instead of printing it.** On MySQL a change written under `binlog_row_image` = `MINIMAL` or `NOBLOB` (a session override counts) was printed to stdout as positional values with no column names (`"after":["C1x"]` for a four-column table), the run exited 0 and the checkpoint moved past it (0.32.2 and earlier); an SQL Server capture instance with fewer columns than its table did the same (`after=[1, 10, 1000]` for a four-column table), and without `--table` it did so with no check at all. A before image short of its column names under a whole after image (`NOBLOB` with only a `TEXT` column changed; `MINIMAL` with every column set) was printed positionally too. `rivet run` with `mode: cdc` and `rivet cdc --output` already refused these. **Now** the stdout drain stops with `RIVET_SOURCE_CDC_PREREQUISITE` (exit 1) before the line, naming the table and the counts, and the checkpoint stays where it was, so a repeat is refused the same way. **Changed stops:** (1) a stdout drain that meets a partial after or before image of a listed table; (2) a stdout drain opened while the MySQL global `binlog_row_image` is `MINIMAL` or `NOBLOB`, even when only unlisted tables were written; (3) a stdout drain of an SQL Server capture instance that omits a column of its table, now with or without `--table`. Whole images, key-only deletes, unlisted tables and `--max-events 0` print as before. **What to do:** set `binlog_row_image = FULL` for every writer (and enable the SQL Server capture instance with the full column list), then follow the printed steps (MySQL: delete the checkpoint file and drain once to re-anchor; the open-time refusals print the setting to change instead); changes written before that anchor are not printed again, so re-sync the consumer from the table. A checkpoint written before the upgrade stays valid: a pre-upgrade run that already printed a partial line is not repaired (nothing marks it afterwards), a pending partial change is refused on the first drain after the upgrade; verified with a run of the previous binary followed by this one on the same checkpoint, then the re-baseline and a FULL update printed whole.
