- **The release gate seeded MySQL with every non-ASCII literal double-encoded, and its golden held the mangled bytes.** `mysql` read the seed on stdin as latin1, so `'unicode: 日本語 🚀'` was stored as mojibake and `dev/release-oracle/golden/duckdb_type_matrix.json` was blessed from it. Every harness `mysql` argv now comes from one helper that sets `utf8mb4`, a lint refuses a hand-spelled one, and each SQL engine's seed is read back from the server (hex of the stored bytes against the seed text): a mismatch is a seed error for that engine and version, never a cell result. The mysql golden row was re-blessed. Harness only; no product change.
