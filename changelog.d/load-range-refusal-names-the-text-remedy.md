- **A date or timestamp `rivet load` refuses as `RIVET_LOAD_VALUE_OUT_OF_TARGET_RANGE` now says how to keep it: declare the column `text` under `columns:`, or cast it to text in the export's `query:`.** Behaviour change in the refusal text only; the exit code (5) and the refusal itself are unchanged. Before, the message named only a `CAST` in the export's `query:`. **Now** it also names `columns: {c: text}`, which delivers the column's value as text through the ordinary export: a ClickHouse `DateTime64` or `Date32` outside 1900-01-01 to 2299-12-31 and a BigQuery date outside 0001-01-01 to 9999-12-31 then land in a `String`/`STRING` column. Verified live on ClickHouse for MySQL `DATE`, `DATETIME(3)`, `DATETIME(6)` and Oracle `DATE`, `TIMESTAMP(6)`, and on BigQuery for MySQL `DATE`: every row, the refused ones included, reads back from the warehouse as the source's value in the text form rivet prints (MySQL `1000-01-01 00:00:00.000000`, Oracle `0001-01-01T00:00:00.000000`). PostgreSQL and SQL Server do not read a date or timestamp as text under `columns:` yet (the export stops with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH`); there the `query:` cast is the remedy that works. Nothing is written by a refused load, so no table exists to migrate; a table loaded before the upgrade is not touched. **What to do:** none for a load that succeeds; for a refused one, declare the column `text` (MySQL, Oracle) or cast it in `query:` (any source), and run the export and the load again.
- **The ledger and the docs name the BigQuery expressions that read an `INT64` nanosecond column back as a native value.** A SQL Server `datetime2(7)` / `datetimeoffset(7)` still lands as `INT64` nanoseconds on BigQuery (no delivery change). `TIMESTAMP_MICROS(DIV(col, 1000))` is the instant, `DATETIME(TIMESTAMP_MICROS(DIV(col, 1000)), 'UTC')` the `datetime2`, `MOD(col, 1000)` the nanoseconds a `TIMESTAMP` cannot hold; before 1970 a value with a sub-microsecond part takes the floor form listed in `docs/type-mapping.md`. Verified on BigQuery against SQL Server's own text for every row to the 100 ns tick.
