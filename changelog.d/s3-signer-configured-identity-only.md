- **Behaviour change (S3 destinations)**: the S3 signer uses only the configured identity. Static keys (`access_key_env` / `secret_key_env`) are signed with the configured `session_token_env` only, never an ambient `AWS_SESSION_TOKEN`; `allow_anonymous: true` sends unsigned requests and ignores every ambient `AWS_*` identity. `allow_anonymous: true` beside `aws_profile` or any key field, and `session_token_env` without `access_key_env` + `secret_key_env`, are now refused with `RIVET_CONFIG_DESTINATION_AUTH_INVALID` (exit 1) at config load. Remedy: remove `allow_anonymous` to sign with the configured keys, or remove the key fields to go anonymous; add the missing key fields beside a session token. (see #920)
