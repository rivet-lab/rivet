- **A SQL Server `xml` column is now delivered as the server's text, not refused (behaviour change, 2026-11-25).** Through the previous release a batch export of an `xml` column stopped before any file was written with `RIVET_TYPE_UNSAFE_MAPPING`, and a CDC export stopped with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (`no decoder for a captured Xml`). **Now** the column is a `string` column (`Utf8`) holding exactly `CAST(col AS nvarchar(max))`, NULL where the source is NULL, with the same text from batch, the CDC baseline and the CDC stream. Tables and state written before the upgrade are untouched: an export that was refused wrote nothing, and an export that declared the column in `columns:` reads and delivers it as declared. **What to do:** nothing; to keep a refusal, or to get another type, declare the column in `columns:`; a downstream table that expected no such column reads it as a string.
