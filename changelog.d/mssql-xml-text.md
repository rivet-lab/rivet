- **A SQL Server `xml` column is now delivered as the server's text, not refused (behaviour change, 2026-11-25).** Through the previous release a batch export of an `xml` column and a CDC export with an initial snapshot stopped before any file was written with `RIVET_TYPE_UNSAFE_MAPPING`, and a stream-only CDC export stopped with `RIVET_SOURCE_CDC_CELL_UNSUPPORTED` (`no decoder for a captured Xml`) on the first captured window that held a non-NULL `xml` value. **Now** the column is a `string` column (`Utf8`) holding exactly `CAST(col AS nvarchar(max))`, NULL where the source is NULL, with the same text from batch, the CDC baseline and the CDC stream. A batch or snapshot export that was refused wrote nothing, and an export that declared the column in `columns:` reads and delivers it as declared. A stream-only export whose first windows held only NULL `xml` values could have delivered those windows before it refused on a later valued cell; those rows carry the column as NULL and stay as written. No test covers a `__changes` table written before the upgrade by a stream-only export that had delivered such windows, so that case is not verified. **What to do:** nothing; to keep a refusal, or to get another type, declare the column in `columns:`; a downstream table that expected no such column reads it as a string.
