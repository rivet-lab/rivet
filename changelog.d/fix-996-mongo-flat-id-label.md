- **Behaviour change: the flat `_id` column of a MongoDB export was labelled `rivet.native_type = objectid` and `rivet.fidelity = exact` over int, string and mixed `_id` values (#996).** Every batch and CDC part carried that label in its Parquet field metadata since the first release, whatever the collection held. **Now** the label follows the lowest and highest `_id` of the collection: all ObjectId keeps `objectid` / `exact`; one other BSON type is named (`number (int, long, double or decimal)`, `string`, `date`, ...) with `logical_string`; more than one type is `mixed` with `logical_string`. The value of every cell, the column's Arrow type, the schema-drift check and the state are unchanged. **What to do:** a reader that keys on `rivet.native_type = objectid` for a collection that does not hold ObjectIds must read the new name; nothing else changes.
