- **`source.columns_from: grants` now works on SQL Server, batch and CDC (#713, part of #711).** A SQL Server login granted `SELECT` on some columns of a table (`GRANT SELECT ON dbo.t (id, name)`) can be refused today by the server at `SELECT *`, and a change stream could never be limited to those columns. **Now** with `columns_from: grants` batch reads and the baseline snapshot select only the columns the server says the login may read, and the change stream is read from a capture instance that holds exactly those columns. **Behaviour change:** SQL Server used to refuse the key at config load (`RIVET_CONFIG_SOURCE_MODE_UNSUPPORTED`); it is accepted now, so a config that carried it is no longer refused. A capture instance that holds a column the login may not read, or leaves a readable one out, is refused with `RIVET_SOURCE_CDC_PREREQUISITE`, because the server returns nothing to a reader of an instance wider than its grants. **What to do:** create an instance over the readable columns (`sys.sp_cdc_enable_table ... @captured_column_list = N'[id], [name]'`), point `cdc.capture_instance` at it, and re-baseline the export with `cdc.initial: snapshot` (a checkpoint taken on the old instance cannot resume on the new one and is refused as a log gap); grant the login `SELECT ON SCHEMA::cdc`. No state or table written before the upgrade changes: the key was refused before.
