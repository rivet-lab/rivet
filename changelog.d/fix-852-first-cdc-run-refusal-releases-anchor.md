- **Behaviour change: a first CDC run that is refused after it created its anchor now releases the anchor (see #852).** `rivet run` creates the PostgreSQL replication slot (or the MySQL, SQL Server, MongoDB and Oracle checkpoint) and records the captured tables before the snapshot legs read anything, so a run refused after that point (a source override wire mismatch, a type builder refusal) left a slot that kept the source retaining WAL, or a checkpoint that a later run read as a stream already begun. **Now** a run that ends in an error on the first run of its stream, with no checkpoint, no baseline marked done and no delivered part recorded before it, drops the slot it created, deletes the checkpoint and forgets the captured-tables record, so the next run starts the stream clean. A slot or checkpoint that existed before the run, or that another stream owns, is never touched, and a run that delivered anything keeps its anchor. The exit code and the refusal code of the run do not change. If the release itself fails, the run keeps its exit and prints `RIVET_SOURCE_CDC_ANCHOR_NOT_RELEASED` with the object and the command that removes it. **What to do:** nothing. A slot or checkpoint leaked by an earlier version is treated as one that existed before the run and is kept: remove it by hand (`SELECT pg_drop_replication_slot('<slot>')`, or delete the checkpoint file) if the export never delivered.
