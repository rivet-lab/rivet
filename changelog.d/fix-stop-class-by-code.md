- **A stop's exit code was read from the words of its message and of the names inside it, so a table called `login_timeouts` or `dns_zones` exited 2 (retryable) on SQL Server, Oracle and MongoDB where PostgreSQL and MySQL exit 1, and a typed transient failure behind a wrapper exited 1.** The exit of an environment stop that carried no typed class was decided by matching words (`timeout`, `dns`, `connection reset`, `temporarily`) in the message, and the message holds the operator's own object names. A MySQL server shutdown (1053) or a SQL Server lock wait that timed out (1222) behind `RIVET_SOURCE_QUERY_FAILED`, a `recoded` stop or `rivet doctor` lost its typed verdict on the way and exited 1. **Now** every environment code declares what decides its exit: a fact (exit 1 whatever the message says), a run-again remedy (exit 2 whatever the message says), or the typed verdict of the failure it wraps (a driver error number, an `io` kind, a SQLSTATE; SQL Server 1205 and 1222 are now decided by the driver number instead of a word in the message: the exit of 1205 is unchanged, but its extra in-run backoff, 1000 ms from the word "deadlock", is now 0, because the number puts it on the same-connection retry with the standard backoff). The numbers that name an object, a column or a privilege the operator chose are typed permanent too, so a column or table called `login_timeout` or `dns_cache` exits 1 on every engine: SQL Server 102, 156, 207, 208, 229 and 230, MySQL 1051, 1052, 1054, 1142 and 1143, and the `ORA-` number the Oracle driver reports for a database error 900, 904, 933, 936, 942 and 1031 (read from the driver's own error number, not from the text). A number rivet does not type, and a wrapper code raised without its cause, still read the words of the message as before. `rivet doctor` exits by the typed verdict of the probe that failed, and the CDC setup hint is chosen by the stop's code and then by an engine `cdc` segment of the message (`cdc:`, `pg cdc:`, `oracle cdc:`) wherever it stands in the chain, not by a `cdc:` echoed inside a driver message. The CDC setup hint is no longer appended to coded stops of class Never, Always, Usage or Refusal. **Changed stop (exit 1 to 2):** `RIVET_SOURCE_COLUMNS_CHANGED_UNDER_READ`, `RIVET_DEST_OBJECT_NOT_FOUND`, `RIVET_DEST_UPLOAD_CORRUPTED` and `RIVET_LOAD_RUN_LANDED_DURING_LOAD` now exit 2, because their registry remedy is to run again; a scheduler that retries exit 2 retries them. **Changed stop (exit 2 to 1):** `RIVET_SOURCE_TABLE_NOT_FOUND`, `RIVET_SOURCE_COLLECTION_NOT_FOUND`, `RIVET_CONFIG_FILE_UNREADABLE`, `RIVET_CONFIG_SECRET_UNSET`, `RIVET_DEST_CONTAINER_NOT_FOUND`, `RIVET_LOAD_WAREHOUSE_ACCESS_DENIED`, `RIVET_LOAD_WAREHOUSE_OBJECT_NOT_FOUND`, `RIVET_SOURCE_STATEMENT_TIMEOUT`, `RIVET_CLI_EXECUTABLE_UNRESOLVED` and `RIVET_STATE_FILE_CORRUPT` exit 1 whatever words their message holds; `RIVET_CONFIG_FILE_UNREADABLE` also exits 1 when the read timed out on a network filesystem, where the `io` kind gave 2 before. `RIVET_CLI_CHECK_REPORTED_ERRORS` is declared exit 1 and already exited 1. **Changed stop (exit 1 to 2):** a SQL Server read that waited past `tuning.lock_timeout_s` (1222; a deadlock victim, 1205, already exited 2) is retried in the run like any transient read failure and exits 2 once the retries are spent; on 1222 the first attempt still fails within `lock_timeout_s`, the retry reads again after the backoff. Nothing in state or in written tables changes. **What to do:** nothing, unless a scheduler's retry list was written around the old exit of these codes; docs/reference/errors.md lists the exit of every code.
