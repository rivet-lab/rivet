- **A Snowflake load of a JSON number that Snowflake would render as an infinity is refused by rivet before any write, as `RIVET_LOAD_VALUE_OUT_OF_TARGET_RANGE` (exit 5).** Behaviour change. `rivet load` loads a JSON column (a MongoDB `document`, a PostgreSQL `jsonb`, a MySQL `JSON`) into a Snowflake `VARIANT` through `PARSE_JSON`, which stores a number written in scientific notation as a double, and Snowflake renders a double at 16 significant digits: the largest finite double `1.7976931348623157e+308` reads back as `1.797693134862316e+308`, larger than any double, so a reader of the text gets an infinity. Before, the load succeeded and the value was read back as an infinity. **Now** `rivet load` reads the `VARIANT` columns of each staged part of a Snowflake plan before the write and stops on such a number, naming the part, the column and the number, in every load mode. Only a finite double whose 16-digit rendering overflows is refused; every other JSON number, string and table loads as before, and a plan with no `VARIANT` column reads nothing extra. Tables and state written before the upgrade are untouched: a run already loaded is not reloaded, and a run staged before the upgrade that holds such a number is refused on its next load. **What to do:** deliver the column as text (cast it in the export's `query:`), or for MongoDB set `source.mongo.json: canonical` and re-export, which keeps the double as the string `{"$numberDouble":"…"}`, or correct the value at the source. Live Snowflake verification of this refusal is pending the account's quota.
