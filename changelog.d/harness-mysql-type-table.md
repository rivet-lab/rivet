- **The MySQL type mapper had no table that pinned what each native type becomes.** The PostgreSQL, SQL Server and Oracle mappers each have one, and a refactor of the MySQL mapping could change a delivery form, a fidelity or the override pairs a type reads with no offline test naming the type. **Now** `the_mysql_type_table_is_pinned` pins, per MySQL wire type, the Rivet type, the Arrow type, the delivery form, the fidelity and every source-to-target override pair `override_table` reads, through the shared helper in `src/types/characterization.rs`. Rows that are known reds carry their `known_red.py` class (`# red:CLASS`); rows another change is moving (`TINYINT(1)`, `BIT`, `TIME`) carry `# under-change` and pin today's behaviour. No product code changed.
