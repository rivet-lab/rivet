- **A PostgreSQL or Oracle INTERVAL column was written as ISO 8601 text with no `rivet.text_form` label (#851).** The values were already the canonical duration text, but the part's field carried only `rivet.fidelity = compatible`, so a reader could not tell a duration from a free string. **Now** the column is delivered as `Utf8` with `rivet.text_form = iso8601_duration` and `rivet.fidelity = logical_string`, in PostgreSQL batch and CDC and in Oracle batch (Oracle CDC refuses INTERVAL by name). **Behaviour change:** the Parquet field metadata of an INTERVAL column differs from earlier parts (`rivet.fidelity` and the new `rivet.text_form`); the values, the column name, the Arrow type and the load spec's target type are unchanged, and `rivet run` over existing state reports `schema: unchanged`. **What to do:** nothing; parts written before the upgrade stay valid and load beside new ones, and a reader that keys on `rivet.fidelity = compatible` for an interval column should accept `logical_string`.
