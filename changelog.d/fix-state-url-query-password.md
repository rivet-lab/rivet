- **A password written as a query pair of `RIVET_STATE_URL` (`?password=…`, `?sslpassword=…`) was printed in clear by `rivet doctor` and by `rivet state copy --to`; a percent-encoded key (`?pass%77ord=…`) was printed by every message that names the URL, error paths included.** The state backend masked only the `user:password@` part with a redactor of its own; the general redactor every log line goes through already masked query pairs. **Now** the state backend has no redactor of its own: every message that names a state URL goes through the general one, so a userinfo, keyword/value or query-pair password is masked in any spelling, and a percent-encoded query key is read decoded. **Behaviour change:** a state URL in a message now shows `postgresql://REDACTED@host/db` instead of `postgresql://user:***@host/db`, so the user name is no longer shown; the full URL stays in your environment. **What to do:** nothing; read the user name from `RIVET_STATE_URL` where you set it.
