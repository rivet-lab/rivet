- **Behaviour change: `rivet doctor` now stops with the cursor refusals `run` gives, instead of exiting 0 over an incremental export `run` refuses.**
  Before, `rivet doctor` passed (exit 0) for an export whose `cursor_column` can hold NULL or has a type the cursor cannot render, while `rivet run`, `check`, `plan` and `apply` ended `RIVET_PLAN_CURSOR_NULLABLE` or `RIVET_PLAN_CURSOR_TYPE_UNSUPPORTED` (exit 5). A pre-run check did not name what `run` would do.
  **Now**, once the source answers, `doctor` asks the source about the `cursor_column:` of each `mode: incremental` export, through the one admission `run` uses, and prints an `Incremental cursor <export>.<column>` line (in the text report and in `--json`): `[FAIL]` with the refusal message and exit 5 `RIVET_PLAN_CURSOR_NULLABLE` or `RIVET_PLAN_CURSOR_TYPE_UNSUPPORTED` for a refused cursor; `[OK]` for an admitted one; `[OK]` naming the cause for a source that cannot be asked about the column, as `run` warns about it. Configs with no incremental export print and exit as before.
  **What to do:** the same as for `run`: make the cursor column NOT NULL, or set `incremental_cursor_mode: coalesce` with a NOT NULL `cursor_fallback_column:` and run `rivet state reset -c <config> --export <name>` once; for an unrenderable type use an integer, text, date, timestamp or uuid column, or `mode: chunked` / `full`. A CI step that ran `rivet doctor` over such a config and passed will now fail until then.
