- **Behaviour change: a CDC stream whose checkpoint file is gone is refused instead of re-anchoring at the current position** (MySQL, SQL Server, MongoDB and Oracle with `cdc.checkpoint:`; PostgreSQL anchors in its slot and is unchanged). A changes-only stream (`initial: none`) whose checkpoint file disappeared (a task landing on another worker, a recreated volume) anchored at the current binlog position, LSN, resume token or SCN, logged a warning and ended with exit 0, silently skipping every change committed since the lost position (0.32.2 and earlier). **Now** the run stops with `RIVET_SOURCE_CDC_CHECKPOINT_INVALID` (exit 5) when the state DB records that the export wrote the checkpoint on an earlier run; `initial: snapshot` streams with a finished snapshot were already refused. **What to do:** restore the checkpoint file; or accept the loss of the changes in the gap and anchor at the current position with `rivet state reset -c <config> -e <export>`; or re-baseline (`cdc.backfill:` or a fresh `initial: snapshot`). A first run, and an export the state DB has never seen, anchors as before. Upgrade: the record is written by the first run of this version (before the run when the file exists, and after it), so a checkpoint already lost before that first run is not detected; the destination and state need no step.
