- **Behaviour change**: a SQL Server `geometry`, `geography` or `hierarchyid` column (every CLR user-defined type) now carries `rivet.text_form: hex_bytes` and the fidelity `logical_string`, where it carried no label and `exact`. The delivered values are unchanged byte for byte: the lowercase hex of the CLR serialization, equal to `CAST(c AS varbinary(max))`, with the SRID inside the bytes, in batch and in CDC. The label shows in the Parquet field metadata, in `rivet check --type-report` and in the load spec; the Arrow type stays `Utf8`, so no schema drift is reported and a table written before the upgrade needs no change. The hex is not WKB. **What to do:** to deliver WKB, select it in the export's `query:`, `SELECT id, g.STAsBinary() AS g_wkb, g.STSrid AS g_srid FROM ...` (`STAsBinary()` drops Z and M, `AsBinaryZM()` keeps them); a `columns: {g: text}` declaration does not change the bytes delivered and carries no label.
