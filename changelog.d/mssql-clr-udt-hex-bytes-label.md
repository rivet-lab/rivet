- **Behaviour change**: a SQL Server `geometry`, `geography` or `hierarchyid` column (every CLR user-defined type) now carries `rivet.text_form: hex_bytes` and the fidelity `logical_string`, where it carried no label and `exact`. The delivered values are unchanged byte for byte: the lowercase hex of the CLR serialization, equal to `CAST(c AS varbinary(max))`, with the SRID inside the bytes, in batch and in CDC. The label shows in the Parquet field metadata and `rivet check --type-report` reports the fidelity `logical_string`; the Arrow type stays `Utf8`, so no schema drift is reported and a table written before the upgrade needs no change. The hex is not WKB. **What to do:** to deliver WKB, select it in the export's `query:`, `SELECT id, g.STAsBinary() AS g_wkb, g.STSrid AS g_srid FROM ...` (`STAsBinary()` drops Z and M, `AsBinaryZM()` keeps them, `STCurveToLine().STAsBinary()` turns a curve into plain WKB; these apply to geometry and geography, not to hierarchyid, whose path text is `h.ToString()`); a `columns: {g: text}` declaration does not change the bytes delivered and carries no label. A second behaviour change follows from the label: a `hierarchyid` column named by `chunk_by_key:` (or a hierarchyid primary key) is now refused before the first write with `RIVET_PLAN_CHUNK_KEY_UNUSABLE` ("Column 'h' is delivered as text, which does not sort as the stored value"); the earlier release admitted it, wrote the first page and then failed on the first cursor bind with `SqlHierarchyId.Parse failed` from the server. **What to do:** key the keyset on an integer, text, uuid, date or timestamp column, range-chunk an integer `chunk_column:`, or use `mode: full`.
