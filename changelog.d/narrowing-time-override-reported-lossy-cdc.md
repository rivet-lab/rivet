- **`rivet check --type-report` on a change-stream (`mode: cdc`) export reports a `columns:` time override that drops sub-microsecond digits as lossy, not exact.** Before, declaring `timestamp` or `timestamp_tz` over an Oracle `TIMESTAMP(7..9)` or a SQL Server `datetime2(7)` / `datetimeoffset(7)` in a CDC export delivered the change rows truncated to microseconds while the report said fidelity `exact` (the batch report was corrected separately). **Now** the CDC report and the run state fidelity `lossy` with the same warning, and `--strict` refuses it as it does any lossy column; the rows are unchanged. **What to do:** to keep the digits, declare `timestamp_ns` / `timestamp_tz_ns` or drop the override; to accept the truncation, nothing.
