- **A crashed checkpointed run resumed under an edited `compression`, `columns` or `meta_columns` finished with one manifest, one schema fingerprint and `_SUCCESS` over parts of two shapes.** The resume check pinned only the query and the chunk settings. **Now** a run records the byte-shaping settings it was opened with (state schema v39, table `run_shape`) and `run --resume`, the next run over an unfinished run, `reconcile` and `repair` compare them: `query`, `format`, `compression`, `compression_level`, `max_file_size`, `skip_empty`, `meta_columns`, `columns` and `parquet` are pinned, and a plan field added later is pinned by default. **Changed stop (behaviour change):** a resume after such an edit now stops with `RIVET_STATE_RUN_SHAPE_CHANGED` (exit 5) instead of exiting 0, on range-chunk, keyset and parallel-keyset runs; so does `reconcile` or `repair` of a run left unfinished under another shape. **What to do:** restore the setting the message names and run once to finish the run, or abandon it with `rivet state reset-chunks -c <config> --export <name>` (range chunks) or `rivet state reset` (keyset) and run again. **Upgrade:** a run left unfinished by an older release has no recorded shape; its first continuation adopts the config as it is then, with a warning, and every later edit is refused. Rolling back to the previous release restores the v38 state from the copy the migration leaves; the `run_shape` table stays and is ignored.
