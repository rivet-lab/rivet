- **A ClickHouse load now lands PostgreSQL `uuid`, `uuid[]` and SQL Server `uniqueidentifier` as a native `UUID` (`Array(Nullable(UUID))` for a list) instead of `FixedString(16)` raw bytes (behaviour change).** A `mode: full` load builds a new table and swaps it in, so the first run after the upgrade replaces a `FixedString(16)` table with a `UUID` one; a query that read the bytes with `hex(col)` or `UUIDNumToString(col)` now reads the `UUID` (`hex` and `toString` give the same text). An incremental or CDC load into a `<table>__changes` that already holds the column as `FixedString(16)` stops before writing with `RIVET_LOAD_TARGET_OBJECT_CONFLICT` (exit 5) and prints the remedy, verified from that state: `ALTER TABLE <changes> ADD COLUMN <col>__uuid Nullable(UUID)`, `UPDATE <col>__uuid = toUUID(UUIDNumToString(<col>)) WHERE 1 SETTINGS mutations_sync = 2`, `DROP COLUMN <col>`, `RENAME COLUMN <col>__uuid TO <col>` (not possible for a key column), or drop `<table>__changes` and `<table>` and load again.
