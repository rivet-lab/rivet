- **A naive timestamp loaded into ClickHouse read back shifted on a server outside UTC.** `rivet load --target clickhouse` declared a timestamp without a zone as `DateTime64(p)`, which ClickHouse shows in the server's time zone: on an Asia/Tokyo server `2024-06-30 23:30` read as `2024-07-01 08:30`, date included, while the load reported success (0.32.2 and earlier). **Now** rivet declares such a column `DateTime64(p, 'UTC')` in every table it creates, so it reads back as written; an incremental or CDC change log created earlier keeps loading as it is, with a warning naming the `ALTER TABLE ... MODIFY COLUMN` that declares the column in UTC. **What to do:** run the `ALTER` from the warning on each older change log (the stored instants do not change); a full load recreates its table with the new type by itself.
