- **A `columns: {c: json}` override over a value that is not JSON now stops the run with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) instead of writing it (behaviour change).** The override only retagged the column as `arrow.json`; a MySQL `GEOMETRYCOLLECTION`, a MySQL `BLOB` of non-JSON bytes, or a `VARCHAR` such as `abc` on PostgreSQL, MySQL, SQL Server or Oracle was delivered unvalidated with exit 0, DuckDB then could not open the file, and `validate --depth full` also passed. A run, batch or CDC, now reads every non-null value of such a column as one RFC 8259 JSON document (nesting depth and number range are not limited) and stops before any write at the first value that is not one; the message names the column and never prints the value. A native `json`, `jsonb` or `JSON` column is delivered as before, declared or not. **Remedy, verified:** declare the column `text` (`columns: {c: text}`) and rivet delivers the server's own text of it; a run that was exit 0 before the upgrade and writes a column no reader can open is now refused at its first such value, its earlier parts stay as written, and the next run after the declaration is changed continues from the same state. `rivet check` reads no values, so it still exits 0 for such a declaration; the refusal is at run.
