- **A resumed range-chunk run finalized a manifest declaring a chunk whose `file_log` row was never written.** A run that failed after a chunk's part was written, with the state database refusing the `file_log` insert (a full disk) while the chunk's own row still completed, left a failed manifest declaring that chunk. The resume over that manifest adopted the part without checking the ledger, and the finished run declared more parts than the ledger recorded; the rows were delivered, but the ledger the run is graded by was short. **Now** a resume reads a completed chunk again whenever the ledger holds no row, or fewer rows, for the part the manifest declares, whether or not the manifest names it; the old part is left out of the manifest. **Behaviour change:** such a resume exports that chunk once more, so one chunk's file is written twice (the first stays on the destination, named by no manifest); state and tables written before the upgrade need no step, and the next `rivet run` over an affected export repairs its ledger by itself.
