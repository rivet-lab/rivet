- **A MySQL `VARBINARY`, `BLOB` or `GEOMETRY` column declared `string` in `columns:` was exported with U+FFFD in place of every byte that is not UTF-8, exit 0, and a MySQL text value that is not valid UTF-8 was written the same way (behaviour change).** A WKB point whose byte is `0xf8` was delivered as `ef bf bd`, so the delivered value was not the one the source holds and nothing said so. **Now** such a value stops the run with `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) naming the column, the byte count and the offset of the first bad byte, and nothing is written for it; a value that is valid UTF-8 is delivered as before. **What to do:** declare the column `binary` in `columns:` to deliver the bytes, or select a text form in the query (`HEX(col)`, `ST_AsText(col)`); a stream or table that already holds U+FFFD from an earlier run is not repaired by the upgrade and is rewritten by a full run after the change.
