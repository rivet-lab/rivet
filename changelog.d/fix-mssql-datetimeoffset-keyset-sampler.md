- **SQL Server: a parallel keyset export keyed on a `datetimeoffset` column up to `datetimeoffset(6)` no longer stops with `RIVET_SOURCE_QUERY_FAILED` (error 241).** With `parallel:` above 1 and a `chunk_by_key` of type `datetimeoffset(0..6)`, the sampler read each split point as a driver debug dump (`DateTimeOffset(Some(...))`), so every range query failed `Conversion failed when converting date and/or time from character string`. **Now** a split point is read as the same ISO text with its offset (`2024-01-01 00:01:00.000000 +00:00`) that a delivered row carries, and SQL Server casts it back to the key's own type. A `datetimeoffset(7)` key stays refused at plan by `RIVET_PLAN_CHUNK_KEY_UNUSABLE`; every other key type reads the same text as before. No state, table or config changes.
