- **`rivet check`, `plan` and `doctor` refuse a batch export whose column the run cannot write, before any row is read.** Behaviour change. Before, `rivet check`, `plan` and `doctor` exited 0 over two kinds of export that `rivet run` then refused: (1) a column the export's `format:` cannot write, that is a `format: csv` export of a column typed `decimal(39..76, s)` (a PostgreSQL `NUMERIC(60,10)` or a `columns:` override to one), a nanosecond timestamp or a list, and a `format: parquet` export of a negative-scale decimal; (2) a column no Arrow type carries and no `columns:` entry declares (PostgreSQL `cidr`, `inet`, `money`, an unbounded `numeric` or a `numeric[]`, and the unmapped types of MySQL, SQL Server and Oracle). **Now** `run`, `check`, `plan` and `doctor` stop at the same point, under `--strict` and without it, with the coded refusal `run` already gave: `RIVET_CONFIG_FORMAT_COLUMN_UNSUPPORTED` (exit 1) for (1) and `RIVET_TYPE_UNSAFE_MAPPING` (exit 1) for (2). The text of the (2) refusal changed: it reads ``N column(s) need a `columns:` declaration`` followed by the column, its source type and the reason, where `run` used to print `N column(s) have no safe Rivet mapping`; a script that matched the old text must match the code. A refusal `run` raises only after it has read rows (a value that does not fit a declared narrower type, `RIVET_SOURCE_VALUE_UNREPRESENTABLE`) cannot be decided before reading and is unchanged. Files, state and tables written before the upgrade are untouched: a config `run` already refused is now refused earlier by the other commands too, and a config `run` ran is not refused. **What to do:** for (1) switch the export to `format: parquet` (or to `csv` for a negative-scale decimal), or cast or drop the column in the query; for (2) cast the column in the query (PostgreSQL `net::text AS net`), or declare its type under `columns:` where the engine accepts that override (a PostgreSQL `cidr` does not accept `string`, so cast it).
