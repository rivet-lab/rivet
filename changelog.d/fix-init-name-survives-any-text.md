- **`rivet init` scaffolded a different table when a catalog name held a line break.** The export `query:` was a folded `>` block, and a folded block turns a line break plus the next line's indent into one space, so a table named `"nl<LF>      tab"` was scaffolded as the twin `"nl tab"`; a column name used as a bare map key (`#tag`, a trailing space, `&a x`) lost its decimal override or collapsed onto a twin column, and a name in a header or note comment could inject YAML keys. **Now** a query whose names hold a line break or a non-printable character is written as one double-quoted scalar, every other query keeps the folded block byte for byte, decimal override and stream-override keys and `capture_instance` are quoted like every other scaffolded value, and comment text is one line. Behaviour change for those names only: a config generated before by `rivet init` for such a name is unchanged on disk and still names the wrong table. **What to do:** re-run `rivet init` for the table and replace the old config; configs generated for ordinary names need nothing.
