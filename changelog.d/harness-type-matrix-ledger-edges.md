- **The edge-value type matrix was hand-run, one engine and one warehouse at a time, and its tables went stale the day they were written.** Every native type of every source engine, its edge values and today's expected verdict lived in `dev/type_edge_matrix` markdown, apart from the ledger the seeds were built from. **Now** `docs/type-capability-matrix.yaml` holds every native type of PostgreSQL, MySQL, SQL Server, Oracle and MongoDB with an `edges:` list per row; an edge is a SQL literal or `{v, x, bigquery, snowflake, clickhouse}` with a verdict of `exact`, `null`, `form:TEXT` or `refuse:CODE@stage`, and a defect carries `NAME!` in front. One module (`type_matrix.py`) builds the seed tables and grades every cell from that row, so the seed path and the expected verdict can no longer drift. `property_no_silent_null_load` grades the cells read back from ClickHouse and DuckDB (the stand lane) and from BigQuery and Snowflake (the new `no_silent_null_load_cloud` lane), each against the source and a second reader, never rivet's own validate line; the lane is census-graded, so an unreachable warehouse is a skip and never a pass. The known defects of the hand-run are accepted reds in `known_red.py`, dated and named by class, so the gate is green today and turns red when behaviour changes either way. Also fixed: `gcp.bq_rows` stopped at the first result page, and the temporal grader ignored digits past the microsecond.
