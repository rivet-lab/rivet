- **`rivet init` wrote configs that depended on state it did not hand over, and a one-table CDC baseline that no timeout could survive.** For an incremental `query:` export `init` wrote `pk: auto`, which `rivet load` could not resolve against any state other than init's own (`RIVET_LOAD_PRIMARY_KEY_MISSING`); and `init --mode cdc` over one table wrote `initial: snapshot`, one full `SELECT` that `statement_timeout_s` stops on a large table. **Now** `init` reads the source primary key and writes `pk: [..]` explicitly when it scaffolds an incremental `query:` export loaded into a warehouse, and a one-table MySQL or PostgreSQL `public` CDC export gets `backfill: auto` with a paged batch export beside it, as two or more tables already did. **What to do:** nothing for existing configs; regenerate with `rivet init` to get the new shape, or write `pk: [..]` by hand.
