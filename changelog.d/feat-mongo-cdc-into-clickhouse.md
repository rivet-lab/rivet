- **Behaviour change: a MongoDB `mode: cdc` export under a ClickHouse `load:` is now accepted, and its change log is ordered by clusterTime and an ordinal.** Until now `rivet check` and `rivet run` refused that config (ADR-0035 CH7). **Now** every Mongo change's `__pos` carries `ct` (the event's clusterTime) and `ord` (its ordinal among the events sharing that clusterTime) beside the resume token, the ordinal is kept in the checkpoint, and the ClickHouse version is `((ct << 64) | ord) << 128`, so events of one transaction, one bulk write or two shards keep the source order across a stop between them. BigQuery and Snowflake still order by the resume token and ignore the new keys; an older rivet reads a checkpoint written by this one. **What to do:** nothing for BigQuery or Snowflake. For ClickHouse, load from a stream whose parts were written by this version. A part written before the upgrade carries a `__pos` without `ct`; the ClickHouse load refuses to insert it and names the remedy: re-baseline the stream so every part is re-written, and truncate the `__changes` table before the next load. A checkpoint written before the upgrade is adopted: the first event after it is stamped `ord = 0`.
