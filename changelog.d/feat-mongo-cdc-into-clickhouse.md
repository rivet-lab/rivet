- **Behaviour change: a MongoDB `mode: cdc` export under a ClickHouse `load:` is now accepted, and its change log is ordered by clusterTime and an ordinal.** Until now `rivet check` and `rivet run` refused that config (ADR-0035 CH7). **Now** every Mongo change's `__pos` carries `ct` (the event's clusterTime) and `ord` (its ordinal among the events sharing that clusterTime) beside the resume token, the ordinal is kept in the checkpoint, and the ClickHouse version is `((ct << 64) | ord) << 128`, so the events of one transaction or one bulk write keep the source order across a stop between them. A change event the server sends without a clusterTime stops the run (`RIVET_SOURCE_CDC_PREREQUISITE`) and the message names MongoDB 4.4 or later as the remedy. **What to do:** nothing for a stream that is new, or already loads into BigQuery or Snowflake. For ClickHouse, a part an older rivet staged carries a `__pos` without `ct` (for example a Mongo CDC export run without `load:` and given a `load:` afterwards). `rivet load` refuses it before it writes anything or creates a table, with `RIVET_LOAD_CDC_POSITION_UNORDERABLE` (exit 5). Re-baseline the stream as the message prints: delete the checkpoint file first (a legacy checkpoint stays the anchor of an idle stream, so a shorter remedy would write the same parts again), move the export's destination files aside, delete its `cdc_snapshot` rows from the state DB, keep `cdc.initial: snapshot`, truncate its `<table>__changes` table if one exists, then run and load again; verified by a live cell that walks it from a part the previous release wrote to a loaded table equal to the source. A checkpoint written before the upgrade is adopted: the first event after it is stamped `ord = 0`. For BigQuery and Snowflake the `__pos` column of a Mongo change row now holds two more keys (`ct`, `ord`), so its bytes differ from before; the order and the views, which read `_data`, are unchanged. For a MySQL, PostgreSQL or SQL Server stream, a ClickHouse change table created by this version has different DDL text for `__ver` with equal values; an existing table keeps its own.
