- **Behaviour change: a MongoDB `mode: cdc` export whose `load:` declares key columns now stops with `RIVET_SOURCE_ID_TYPES_MIXED` (exit 5) when its collection holds `_id` values of more than one BSON type.** Until now such a run exited 0 with only a warning, and the current-state view merged documents whose `_id` render to the same text (int `1` and string `"1"`, an ObjectId and its hex): eight source documents read back as four view rows, and a delete of one removed the other. **Now** the snapshot is refused before it writes, a stream is refused at its open when the collection already mixes types and at the change that would add a second type, and `rivet load` is refused before it appends when the checkpoint records two types. The message lists the types seen. The checkpoint gains a key `idt` (the `_id` types delivered per collection); a checkpoint written by an older release has none, reads as none, and gains it with its next save, and the delivered `_id`, `document` and `__pos` bytes are unchanged. **What to do:** nothing for a collection of one `_id` type, an export with no keyed `load:`, or a `mode: full` export. Otherwise load the collection with `mode: full`, or make its `_id` values one BSON type, drop the change-log table, delete the CDC checkpoint and run again for a fresh snapshot. Loading mixed-type `_id` under a keyed load is tracked in #926.
