- **Upgrading from 0.32.2 — read these first.** Each line below is a thing an operator on 0.32.2 may meet on the first run of 0.33, with its remedy.
- **The state stays at schema v38: 0.33 runs no migration and writes no pre-migration copy, and 0.32.2 can run again on a state 0.33 wrote.** **What to do:** nothing. This is the coordinator's hand probe on incremental, PostgreSQL CDC and MySQL CDC round trips (no gap, no duplicate, Parquet bytes identical); this PR does not re-run it.
- **An export reached under another source address is refused with `RIVET_STATE_CURSOR_SOURCE_RESPELLED` instead of re-reading the table.** **What to do:** `rivet state accept -c <config> --export <name>` moves the progress to the key the config names (changelog.d/fix-source-key-respelled.md, changelog.d/fix-url-authority-at-in-query.md).
- **A first load that failed no longer makes the target rivet's own, so a retry onto that existing table is refused with `RIVET_LOAD_TARGET_NOT_RIVETS`.** **What to do:** if the table is what that first load left, drop it and re-run (changelog.d/fix-613-own-after-first-success.md).
- **A named destination credential stops the run instead of falling back to another credential.** A GCS `credentials_file` that is not a service-account key, an S3 `aws_profile` with no static keys, and one chooser for every leg of a run (#829). **What to do:** point `credentials_file` at a service-account key or remove it; give the profile static keys or remove `aws_profile` (changelog.d/fix-named-credential-never-falls-back.md, changelog.d/fix-s3-named-profile-never-falls-back.md, changelog.d/fix-destination-credential-every-leg.md).
- **A CDC stream whose checkpoint file is gone is refused instead of re-anchored at the current position.** **What to do:** restore the checkpoint file, or `rivet state reset -c <config> -e <export>` to accept the gap, or re-baseline with `cdc.backfill:` or a fresh `initial: snapshot` (changelog.d/fix-cdc-lost-file-anchor.md).
- **A CDC checkpoint that another stream owns is refused with `RIVET_SOURCE_CDC_CHECKPOINT_SHARED`; `rivet cdc` now writes an owner record beside its checkpoint.** **What to do:** give the command a `--checkpoint` of its own; if the command is finished and the export should continue from where it stopped, delete `<checkpoint>.owner` and run the export again (changelog.d/fix-rivet-cdc-claims-its-checkpoint.md).
- **A Snowflake config that names `load.connection:` stops at config load.** **What to do:** write the connection lines under `load:` instead of `connection:` (CHANGELOG.md, Unreleased, the Snowflake bullets).
- **A `mode: cdc` export on Snowflake that names neither `cdc.backfill:` nor `cdc.initial: snapshot` is refused at config load (`RIVET_CONFIG_LOAD_BLOCK_INVALID`).** **What to do:** add one of the two, or write `load.layout: log_view` (CHANGELOG.md, Unreleased, the Snowflake bullets).
- **Snowflake's default layout changed: an incremental or CDC export that writes no `load.layout:` gets a base and a buffer, where it got a changelog and view.** **What to do:** write `load.layout: log_view` to keep the view (CHANGELOG.md, Unreleased, the Snowflake bullets).
- **`rivet compact` on a Snowflake `log_view` table reports `skip_reason: log_view`, not `warehouse_never_compacts`.** **What to do:** key scripts on the JSON `skip_reason` (CHANGELOG.md, Unreleased, the compact bullet).
- **`rivet init --snowflake-role ""` is refused with `RIVET_CLI_VALUE_INVALID` (exit 1).** An empty `--snowflake-role` names no role. **What to do:** leave the flag out to use the user's default role.
- **A stored composite cursor that is not a value tuple of its `chunk_by_key` is refused with `RIVET_STATE_CURSOR_INCOMPARABLE` (exit 5), and nothing is read.** **What to do:** `rivet state reset -c <config> --export <name>` starts the cursor over with a full pass.
- **A malformed secret name is refused with `RIVET_CONFIG_SOURCE_CONNECTION_INVALID` (exit 1).** A `url_secret` or `password_secret` that is not `projects/<project>/secrets/<secret>` (optionally with `/versions/<n>`) is refused, and so are two of `password`, `password_env` and `password_secret` set together. **What to do:** name the secret in that form and set one password source.
- **`RIVET_LOAD_WAREHOUSE_ANSWER_UNREADABLE` (exit 6, internal) is new in 0.33.** `rivet load` and `rivet compact` raise it when Snowflake or BigQuery answers in a shape rivet does not read, when an object-kind probe returns a code outside 0, 1, 2 and 4, or when a compaction range bound has a type the key cannot read. **What to do:** report it with the message.
