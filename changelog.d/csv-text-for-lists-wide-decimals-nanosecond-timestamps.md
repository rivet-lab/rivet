- **`format: csv` now delivers a flat array, a decimal of precision above 38 and a nanosecond timestamp as text, where it used to stop with `RIVET_CONFIG_FORMAT_COLUMN_UNSUPPORTED`.** Behaviour change. Before, an export or CDC stream in CSV that held a PostgreSQL `text[]`, `int[]`, `date[]`, `timestamp[]`, `uuid[]`, `bytea[]` or `numeric(60,10)`, a SQL Server `datetime2(7)` or `datetimeoffset`, or an Oracle `TIMESTAMP(9)` column was refused before any read while the same export in Parquet delivered it (a SQL Server export in `time_window` mode refused every column set, as its time column is `datetime2`). **Now** a flat array is one JSON array text in one quoted field (`["a,b",null,""]`: a NULL element is `null`, an empty list is `[]`, a NULL list is the empty field, a non-finite float is the string `"NaN"` or `"inf"`), a `Decimal256` is its exact plain decimal text, and a nanosecond timestamp is ISO 8601 with nine fraction digits and a trailing `Z` for an instant. A nested array and non-UUID fixed binary stay refused by the same code, naming the column. Nothing was written by a refused run, so there is no state or file to migrate; an export that was moved to `format: parquet` to get past the refusal keeps working, and one switched back to CSV delivers from the next run. A CSV consumer that parses the new columns reads JSON text for an array and nine fraction digits for a nanosecond timestamp. The ledger `docs/type-capability-matrix.yaml` records `csv: text` with a dated reason on each of the 13 rows.
