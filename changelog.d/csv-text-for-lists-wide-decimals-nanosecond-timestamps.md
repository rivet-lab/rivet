- **`format: csv` now delivers a flat array, a decimal of precision above 38 and a nanosecond timestamp as text, where it used to stop with `RIVET_CONFIG_FORMAT_COLUMN_UNSUPPORTED`.** Behaviour change. Before, an export or CDC stream in CSV that held a PostgreSQL `text[]`, `int[]`, `date[]`, `timestamp[]`, `uuid[]`, `bytea[]` or `numeric(60,10)`, a SQL Server `datetime2(7)` or `datetimeoffset`, or an Oracle `TIMESTAMP(9)` column was refused before any read while the same export in Parquet delivered it (a SQL Server export in `time_window` mode refused every column set, as its time column is `datetime2`, which is `datetime2(7)` when written bare). **Now** a flat array is one JSON array text in one quoted field (`["a,b",null,""]`: a NULL element is `null`, an empty list is `[]`, a NULL list is the empty field, a non-finite float is the string `"NaN"` or `"inf"`), a `Decimal256` is its exact plain decimal text, and a nanosecond timestamp is ISO 8601 with nine fraction digits and a trailing `Z` for an instant. A nested array and non-UUID fixed binary stay refused by the same code, naming the column. Nothing was written by a refused run, so there is no state or file to migrate; an export that was moved to `format: parquet` to get past the refusal keeps working, and one switched back to CSV delivers from the next run. A CSV consumer that parses the new columns reads JSON text for an array and nine fraction digits for a nanosecond timestamp. Every column the previous release already delivered in CSV is written byte for byte as before: a `datetime2(0..6)`, `datetime`, `smalldatetime`, `datetimeoffset(0..6)`, `date` and `time(6)` keep their six fraction digits (`2026-01-15T13:45:30.123456`, `...123456Z`), proven by the same table exported by the previous release and by this one (identical md5) and pinned by a live cell. A SQL Server `datetime2(7)` or `datetimeoffset(7)` was written in CSV with six digits by 0.32.x and earlier (the 100 ns tick dropped) and refused by 0.33.0; it is now written with all nine digits (`2026-01-15T13:45:30.123456700`), so an export that went back to CSV after 0.33.0 refused it reads the seventh digit for the first time. The ledger `docs/type-capability-matrix.yaml` records `csv: text` with a dated reason on each of the 13 rows.
