- **Redaction panicked, exit 101, on a URL query key that percent-decodes to a multi-byte character before a password keyword.** A key such as `?%FFn=` decodes to `U+FFFD` followed by `n`, and the keyword check cut that text at a byte offset inside the character; the same check ran on every log line, error message and plan artifact that names a URL (since 0.32.0 at the latest). **Now** the keyword is matched on bytes, so no text can crash redaction, and a password keyword after a decoded multi-byte character (`?%E2%82%ACpwd=…`) is masked. **What to do:** nothing.
