- **A SQL Server `datetime2`, `datetimeoffset`, `datetime` or `smalldatetime` column declared `text` (or `string`) under `columns:` is now delivered as the server's own text, for every year from 0001 to 9999.** Behaviour change. Before, the declaration was refused at plan time with `RIVET_SOURCE_OVERRIDE_WIRE_MISMATCH`, so a `datetime2(7)` or `datetimeoffset(7)` value outside 1677-09-21..2262-04-11, which the nanosecond default refuses with `RIVET_SOURCE_VALUE_UNREPRESENTABLE`, had no remedy that kept its seventh digit. **Now** the declaration is read and the column lands as `Utf8` holding `YYYY-MM-DD hh:mm:ss[.fraction]` at the type's scale (`datetimeoffset` adds ` +hh:mm`); the refusal for an out-of-range value names `<column>: text` as the first remedy. The `datetime2(7)` / `datetimeoffset(7)` default is unchanged: it stays `Timestamp(ns)` and still refuses a value outside the nanosecond range. Tables, state and exports written before the upgrade are untouched: no config that ran is read differently, and only a config that declared `text` over these types (refused before) now runs. **What to do:** to carry an out-of-range value, add `columns: {<column>: text}` to the export; to keep the previous behaviour, change nothing.
