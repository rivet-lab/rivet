- **A batch export onto a destination prefix that holds a CDC manifest now refuses before it stores anything.** The refusal `RIVET_DEST_PREFIX_MODE_MISMATCH` ("already holds a 'cdc' manifest ... refusing to overwrite") was raised by each runner after it had already stored its plan: a parallel chunk-checkpoint run left an `in_progress` chunk run with pending tasks, and the keyset runners (sequential, parallel, incremental) had already recorded their resume run id, their ranges or their anchor. **Now** the dispatcher raises the refusal once, before any runner starts, so a refused run leaves no plan, anchor or cursor behind. **Behaviour change:** the run still stops with the same code and exit; what differs is the state it leaves. **What to do:** nothing for new runs. A plan or anchor that a refused run wrote before the upgrade stays in the state database untouched; point the export at a prefix of its own and it runs as before.
