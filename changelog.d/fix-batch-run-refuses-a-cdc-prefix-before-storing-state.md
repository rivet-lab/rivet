- **A batch export onto a destination prefix that holds a CDC manifest now refuses before it stores a plan, an anchor or a cursor.** The refusal `RIVET_DEST_PREFIX_MODE_MISMATCH` ("already holds a 'cdc' manifest ... refusing to overwrite") was raised by each runner after it had already stored its own progress: a parallel chunk-checkpoint run left an `in_progress` chunk run with pending tasks, and the keyset runners (sequential, parallel, incremental; MongoDB with `page_size` and `resume: true`) had already recorded their resume run id, their ranges or their anchor. **Now** the dispatcher raises the refusal once, before any runner starts, so a refused run leaves no plan, anchor or cursor behind (its run record and observed schema are still written, as for every refused run). **Behaviour change, two parts.** (1) The stop is the same code and exit; what differs is the state it leaves. A plan or anchor that a refused run wrote before the upgrade stays in the state database untouched; point the export at a prefix of its own and it runs as before. (2) A `skip_empty: true` export that finds no rows, run over a prefix that holds a CDC manifest, used to exit 0 as a skipped run; it now stops with `RIVET_DEST_PREFIX_MODE_MISMATCH`, exit 5, like every other batch run over that prefix. **What to do:** give the export a destination prefix of its own; a batch and a CDC export must not share one.
