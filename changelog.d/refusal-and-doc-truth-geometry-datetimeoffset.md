- **Three message and doc corrections; no delivered value changes.** (1) The Oracle refusal of an object or collection column (`RIVET_TYPE_UNSAFE_MAPPING`) now names the `query:` forms that read it: an object type's scalar attributes (`t.col.attr`), a collection's elements through `TABLE(t.col)`, or leaving the column out, and the functions Oracle documents for `SDO_GEOMETRY` (`SDO_UTIL.TO_WKBGEOMETRY`, `SDO_UTIL.TO_WKTGEOMETRY`); the Spatial functions were not run, because the stand's Oracle image has no Spatial. (2) The SQL Server nanosecond refusal (`RIVET_SOURCE_VALUE_UNREPRESENTABLE`) over a `datetimeoffset` no longer advises `text` for a stream-only CDC export, because the change stream drops the offset and widens the fraction (`2300-01-01 00:00:00.0000001 +02:00` arrives as `2299-12-31 22:00:00.000000100`); it names `text` for a batch export only and `timestamp_tz` for a CDC export. The refusal over a `datetime2` is unchanged, and a stream-only export declared `text` over a `datetimeoffset` keeps delivering the stream's text as before. (3) `docs/reference/config.md` no longer says a PostGIS `geometry` or `geography` is refused before the run: rivet reads any PostgreSQL type with no Arrow mapping as the server's text, and PostGIS is covered by an offline test only. Nothing is stored differently; no state or table written before the upgrade is affected.
