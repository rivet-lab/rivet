- **Behaviour change: a MongoDB `mode: cdc` export whose `load:` leaves `pk` at its default now stops with `RIVET_SOURCE_ID_TYPES_MIXED` (exit 5) over `_id` values of more than one BSON type, as an explicit `pk: [_id]` does.** The `_id` type guard ran only for a `load:` that spelled its key columns, while `pk: auto` (the default) resolves to the source key `_id` at load, so a collection holding `{_id: 1}` and `{_id: "1"}` collapsed to one view row at exit 0. **Now** the guard reads the same answer the load plan does: `auto`, an omitted `pk` and explicit key columns are keyed, only `pk: none` or no `load:` block is not. The snapshot, the stream open, the change of a second type, `rivet check` and `rivet load` refuse, and the checkpoint records `idt` for these exports too (an older checkpoint without it reads as none and gains it with its next save). **What to do:** nothing for a collection of one `_id` type or an export with `pk: none`. Otherwise load the collection with `mode: full`, or make its `_id` values one BSON type, drop the change-log table, delete the CDC checkpoint and run again for a fresh snapshot.
