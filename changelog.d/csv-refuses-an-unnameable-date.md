- **`format: csv` stops by `RIVET_SOURCE_VALUE_UNREPRESENTABLE` (exit 5) on a date or microsecond timestamp outside the years -262143..+262142, where it wrote an empty cell.** Behaviour change. Before, the CSV writer wrote nothing for a Date32 or microsecond timestamp that chrono cannot name (a bare empty field, or `""` inside a list), and an empty field reads as NULL, so the value was lost silently. **Now** the run stops naming the column and the value, and writes no part. No source rivet reads can deliver such a value today (PostgreSQL `infinity` and years past 262142 are refused at the source by the same code, MySQL, SQL Server and Oracle stop at year 9999, MongoDB dates are millisecond instants inside the range), so no existing export changes; the refusal guards a future or hand-built source. A date in range, including `+10000-01-01` and `-262143-01-01`, are written byte for byte as before. Remedy for a refused column: select it as text with a `CAST` in the export's `query:`, or use `format: parquet`.
