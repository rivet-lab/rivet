- **`rivet check`, `rivet doctor` and `rivet plan` passed configs that `rivet run` refuses.** Behaviour change. Each pre-run command kept its own copy of a run decision (override admission, missing relation, settle and strict columns, the `{partition}` token of a `partition_by` export), so a config could pass `check` and stop at `run`. **Now** one planning module plans and admits every batch export exactly as `run` does, and `check`, `doctor` and `plan` call it and stop before the first write; they refuse with the code `run` would raise. `rivet plan --output <file>` on a `partition_by` export now refuses to seal with `RIVET_PLAN_PARTITION_TOKEN_UNEXPANDED` (it used to write an artifact that `rivet apply` then refused). Files and tables written before the upgrade are unchanged. **What to do:** run `rivet check` on every config; for a `partition_by` export run `rivet run` or `rivet apply <config.yaml>` instead of sealing a plan.
