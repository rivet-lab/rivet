- **Behaviour change: a `sqlserver://` URL with a bracketed IPv6 host and no port was refused, and the `sqlserver://` database and the `oracle://` service name were used with their `%XX` bytes undecoded.** `sqlserver://u:p@[::1]/db` stopped with `mssql url port not a number: 1]`; `sqlserver://u:p@h/Sales%20DB` opened the database `Sales%20DB`; `oracle://u:p@h/ORCL%2Edomain` connected to the service `ORCL%2Edomain`. **Now** both parsers share one bracket-aware host/port split in `url_text` (a v6 host without a port defaults to 1433 / 1521) and percent-decode the database and the service name like the userinfo; an Oracle service whose decoded text holds `/` (an encoded `%2F`) is refused as a raw `/` is. **What to do:** nothing for URLs built by rivet; a database or service whose real name contains a literal `%XX` must now be written with the `%` itself encoded as `%25`.
