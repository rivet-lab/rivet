- **A BigQuery access token echoed back by the warehouse is masked in rivet's output.** Before, a token held in `RIVET_BQ_ACCESS_TOKEN` or obtained through ADC was masked only where a call site registered it, and the BigQuery path did not: a server that returned the `Authorization` header in its error body (a 401 from a proxy or a misconfigured endpoint) had the token printed verbatim in stderr and in `--summary-output`. **Now** a credential held as a `Secret` (the BigQuery token, a database or ClickHouse password from `password`, `password_env` or `password_secret`) is registered for masking when it is read, and prints as `***` wherever it appears in an error text, `--summary-output` or a log. Not registered: a value shorter than 8 bytes; a value that contains `://`, or `=` together with a space or `;` (a connection URL, a keyword DSN, and a service-account JSON key, which holds `https://`), which only the URL and keyword scanners mask, by their password; and a password that is exactly the word `password`, because masking that word in free text would rewrite rivet's own remedy hints (`referenced by password_env`) and hide the real password of `password=<secret>` from the keyword scanner. Any other credential that equals an ordinary word of rivet's messages is masked in those messages too. Where one registered value is a prefix of another, the longer is masked first, so no tail is left. The registry lives for the process and is never wiped. **What to do:** nothing; if an earlier failed BigQuery load printed a token to a log, rotate that token.
