- **A BigQuery access token echoed back by the warehouse is masked in rivet's output.** Before, a token held in `RIVET_BQ_ACCESS_TOKEN` or obtained through ADC was masked only where a call site registered it, and the BigQuery path did not: a server that returned the `Authorization` header in its error body (a 401 from a proxy or a misconfigured endpoint) had the token printed verbatim in stderr and in `--summary-output`. **Now** every credential rivet holds is registered for masking when it is read, so it prints as `***` wherever it appears; a connection URL or DSN is still masked by its password only. **What to do:** nothing; if an earlier failed BigQuery load printed a token to a log, rotate that token.
