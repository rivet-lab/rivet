- **A BigQuery access token echoed back by the warehouse is masked in rivet's output.** Before, a token held in `RIVET_BQ_ACCESS_TOKEN` or obtained through ADC was masked only where a call site registered it, and the BigQuery path did not: a server that returned the `Authorization` header in its error body (a 401 from a proxy or a misconfigured endpoint) had the token printed verbatim in stderr and in `--summary-output`. **Now** a credential held as a `Secret` (the BigQuery token, a database or ClickHouse password from `password`, `password_env` or `password_secret`) is registered for masking when it is read, and prints as `***` wherever it appears in an error text, `--summary-output` or a log. Not registered: a value shorter than 8 bytes; a value that contains `://`, or `=` together with a space or `;` (a connection URL, a keyword DSN, a service-account JSON read as one value, which holds `https://`), which only the URL and keyword scanners mask, by their password; the `private_key` of a service-account JSON is its own `Secret` and is registered unless its PEM holds `=` with a space; and a password that is exactly the word `password` in any case, because masking that word in free text would rewrite rivet's own remedy hints (`referenced by password_env`). Any other credential that equals an ordinary word of rivet's messages is masked in those messages too. Where a registered value is also what a scanner reads (a URL scheme before `userinfo@`, a password or secret key before `=`, a secret query key in any percent-encoding), the scanners mask the credential next to it first and the registered value is masked after them, so a registered `postgres` over `postgres://rivet:OtherPw@db/x` prints `***://REDACTED@db/x`. The bytes a scanner reads to decide where a password value begins and ends are left to it as well: the `;` and blanks before a password key and the first character of its value, so a registered value that covers the `;` before `Password=` leaves that password masked whole. A registered value equal to `REDACTED`, the word the URL scanner prints, is registered like any other, and the `REDACTED` the scanner itself prints stays. Masking an already masked text a second time can still join two masks that touch (`******` becomes `***`); it never exposes a value. A registered value is masked raw and percent-encoded in each of three forms (every non-alphanumeric byte, the URL userinfo set rivet writes into a generated source URL, and form encoding with `+` for a space), each in upper-case and in lower-case hex; an escape that mixes both cases in one text is not matched. Registered values that overlap in a text are masked as one. The registry lives for the process and is never wiped. **What to do:** nothing; if an earlier failed BigQuery load printed a token to a log, rotate that token.
