- **A BigQuery access token echoed back by the warehouse is masked in rivet's output.** Before, a token held in `RIVET_BQ_ACCESS_TOKEN` or obtained through ADC was masked only where a call site registered it, and the BigQuery path did not: a server that returned the `Authorization` header in its error body (a 401 from a proxy or a misconfigured endpoint) had the token printed verbatim in stderr and in `--summary-output`. **Now** a credential held as a `Secret` (the BigQuery token, a database or ClickHouse password from `password`, `password_env` or `password_secret`) is registered for masking when it is read, and prints as `***` wherever it appears in an error text, `--summary-output` or a log. Not registered: a value shorter than 8 bytes; a value that contains `://`, or `=` together with a space or `;` (a connection URL, a keyword DSN, a service-account JSON read as one value, which holds `https://`), which only the URL and keyword scanners mask, by their password; the `private_key` of a service-account JSON is its own `Secret` and is registered unless its PEM holds `=` with a space; and a password that is exactly the word `password` in any case, because masking that word in free text would rewrite rivet's own remedy hints (`referenced by password_env`). Any other credential that equals an ordinary word of rivet's messages is masked in those messages too. The URL, keyword and query scanners read the text as it was, never with a registered value already replaced, so what they mask is what they masked before this change, and a registered value is masked beside it: a registered `postgres` over `postgres://rivet:OtherPw@db/x` prints `postgres://REDACTED@db/x`, as the scanner alone prints it, and the same word elsewhere in the text prints `***`. Where a registered value and a scanner's mask overlap or touch in the text, they print as one `***` (`REDACTED` for a URL userinfo). A text that holds no registered value prints exactly as before: the scanners' output, byte for byte, and a registered value that only the scanners' own tokens would form (`pwd=***&QZ` over `x ?pwd=K9&QZ y`, `REDACTED@hostQZ` over `pg://u:K9@hostQZ`) is not looked for there. A text that holds a registered value is masked so that no registered value remains in the output, including one that a mask or the word `REDACTED` forms with its neighbours, whichever order the values registered in. Tested by 112000 exhaustive short texts and 400000 seeded random ones (values and texts that include tab, newline and `*`): no output of a text holding a registered value holds one, and none shows a byte of a credential that the scanners alone, or a plain replace of the value followed by the scanners (the order before this change), hid. Masking an already masked text a second time never exposes a value. A registered value is masked raw and percent-encoded in each of three forms (every non-alphanumeric byte, the URL userinfo set rivet writes into a generated source URL, and form encoding with `+` for a space), each in upper-case and in lower-case hex; an escape that mixes both cases in one text is not matched. Registered values that overlap in a text are masked as one. The registry lives for the process and is never wiped. **What to do:** nothing; if an earlier failed BigQuery load printed a token to a log, rotate that token.
