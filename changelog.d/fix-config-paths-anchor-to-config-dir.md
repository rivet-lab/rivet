- **A relative `url_file` was read under the working directory while state and destination resolved beside the config, so a run from another directory delivered a different database into the config's destination with exit 0.** One config with `url_file: db.url` read whichever `db.url` sat in the directory rivet started from and wrote to the destination and state beside the config: a run from a directory holding its own `db.url` delivered that database's rows under the config's export, exit 0, and `run_status` held two successes for one export from two different source URLs. The same split held for `tls.ca_file`, the Snowflake `load.private_key_path` and the ClickHouse `load.ca_file`. **Behaviour change.** **Now** every relative file a config names (`url_file`, `tls.ca_file`, `load.private_key_path`, `load.ca_file`, `credentials_file`) is resolved once, at config load, beside the config file, from every directory and every command. **Changed stop:** a relative path whose file only the working directory holds (where earlier releases read it) is refused with `RIVET_CONFIG_SECRET_UNSET` (exit 1) naming both places, so an upgrade never reads another file or switches database silently. **What to do:** move the file beside the config (the refusal names the place), or make the path absolute. A cron job that started from the directory holding the file keeps working when that directory is the config's directory. State and tables written before the upgrade are not touched.
