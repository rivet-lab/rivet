- **`source.columns_from: grants` is now accepted on PostgreSQL (behaviour change; refs #712).** Through the previous release a PostgreSQL config carrying the key was refused at load with `RIVET_CONFIG_SOURCE_MODE_UNSUPPORTED`, and a CDC run without it read `SELECT *` and every column of every decoded row. **Now** a PostgreSQL source with `columns_from: grants` delivers only the columns the account may `SELECT` (column-level and table-level grants, judged by the server with `has_column_privilege`): a batch read selects only them, and the change stream drops the others from every row of a captured table while the slot output is parsed, before it is buffered, spilled or written (data minimisation, not access control: logical decoding does no column privilege check, so the values still reach the rivet process; `rivet check` and the run log say so). The readable set is read once before the anchor; a grant change seen at the next batch read, or between that read and the stream open, is refused with `RIVET_SOURCE_CDC_GRANTS_CHANGED` (exit 2) with nothing of the batch delivered, and a re-run resumes under the new grants. An update of hidden columns only is not delivered under `REPLICA IDENTITY FULL`; under the default identity it is delivered with the readable columns, because the slot carries no old image. An unreadable key or no readable column is refused with `RIVET_SOURCE_COLUMNS_UNREADABLE`. The refusal on SQL Server now reads "supported on MySQL, PostgreSQL, Oracle and MongoDB sources only". State and tables written before the upgrade are untouched: a config without the key reads and delivers every column as before, and a config that carried the key never ran. **What to do:** nothing for configs without the key; to use it grant the account `SELECT (<columns>)` on the table and `REPLICATION`, and set `REPLICA IDENTITY FULL` on the table if an update of hidden columns only must not be delivered.
